# jarvis-write

**一个可控、改得动、不崩的 AI 长篇小说创作系统。**

[English](README_EN.md) | 简体中文

写长篇小说时，AI 工具的头号问题不是"写不出来"，而是写到几十万字后**人设崩、伏笔丢、大纲改不动**。jarvis-write 不是又一个"一键生成器"——生成文字的活交给 LLM，本项目做的是包在 LLM 外面的**控制层**：故事圣经管事实、伏笔调度管回收、大纲级联管改动、倾向标签管风格，让长篇创作全程可控、可改、可追溯。

## ✨ 四个别人没有的杀手锏

市面上的 AI 写作工具大多止步于"生成"，jarvis-write 的价值在于生成之后还**改得动、不崩、你说了算**——尤其这一版，把"一眼读得出是 AI 写的"这个老大难，当成重中之重来攻：

- **🔗 大纲级联更新**——改任意一章大纲，系统自动做改动分级（小改零成本短路）、分析下游影响、你勾选后级联重生成；已有正文自动标记失配，大纲全程版本化可回退。*这一条，同类开源项目里一个都没做。*
- **🧭 长程一致性引擎**——时序故事圣经（每条事实绑生效章节区间，可查"第 N 章时角色是什么状态"）+ 伏笔四态调度（埋设/强化/回收/弃用，到期自动提醒），章后自动抽取实体与事实写回圣经。几十万字不自相矛盾。
- **🎚️ 标签化倾向系统**——风格/节奏/基调不再写死在 Prompt 里：chips + 自定义输入 + 预设模板，贯穿大纲、正文、润色三个节点，全程你说了算。
- **🧬 去 AI 味 · 双向锚定 + 自愈闭环**——把"读得出是 AI 写的"当头号敌人来打：正向喂**名家 / 预设文风范本**（余华、鲁迅、汪曾祺、金庸、王小波、海明威…任选，也可喂自己的范文、或从已认可章节自动提取）给笔法一个具体的"人"去学，负向用 ✗AI 腔→✓人话 配对反例把套话逐条划掉；定稿再过一道**量化 AI 味门禁**（9 类套话规则 + 句长节奏 / 段落结构统计打分），超标就**定向去味重写→复测→收敛**，没改好自动回退、绝不落更差的版本。正向锚一路铺到续写、片段润色、整章润色每一个入口。*名家文风一律标注"风格参考·非原作节选"，范本为本项目自撰仿写，不含任何原作节选。*

## 🎬 漫剧工坊：写完的小说，一键变成漫剧

不止能写、能改——「全书 → 漫剧」把已定稿章节改编成竖屏漫剧的**完整拍摄手册**，从画风到预告片的整条制片流水线，拿去即梦 / 可灵 / Midjourney / 剪映照单施工：

```
① 画风方向拍板        ② 资产卡(一致性锚)      ③ 切集            ④ 单集流水线                ⑤ 预告片
  国漫/二次元/3D/  →    画风锁定段         →    按短剧节奏切  →    剧本 → 分镜表 →        →   30-60s 高能混剪
  水墨/赛博/真人写实    角色锁定外貌段           每集钩子+卡点       三轨绘图提示词              金句文案+标题卡
  (AI 按书荐前三)       场景定调段+定妆照                           成片包:配音稿/剪辑清单/SRT
```

- **一致性是命门**：画风锚、人物锚、场景锚由资产卡统一管理，**逐字注入每一格分镜提示词**（LLM 偶发漏注入时引擎兜底强制拼入）——同一个人不换脸、上百格画风不漂移。*这正是"拍出来像一部剧"和"一百张拼贴"的区别。*
- **定妆照锁脸**：文字锚只能把漂移压小、压不到零——角色卡上一步「出定妆照」，AI 写一条参考图专用提示词（单人正面半身 / 纯色背景 / 3:4，带本书画风锚），你出一张满意的**上传回角色卡**，之后凡这个角色出场的分镜都提示你带上它当垫图。*文字锚 + 参考图，是当前业界最稳的锁脸做法。*
- **提示词一键粘贴，认得你用的生图站**：每格三份现成的——① 只有一个描述框的站（GPT-image / DALL·E / 豆包 / 通义）负面词改写成「【不要出现】…」并入正文，**整段粘一次就行**；② 有负面词框的站（即梦 / 可灵 / SD / ComfyUI）正文与负面词分开粘；③ Midjourney / Niji 用英文 + `--ar 9:16` + `--no`。三份由后端同一套规则生成，站内所见 / 导出手册 / CSV（含 `paste_oneframe` 整段列）完全一致
- **画风方向你拍板**：国漫厚涂 / 日系二次元 / 3D 动画 / 水墨国风 / 赛博霓虹 / 真人写实六向硬约束（真人写实挂恐怖谷警示，动画系为默认推荐）；不确定就「AI 荐方向」——按书的题材/基调荐前三，带理由带优先级，点一下即选中
- **导演知识已编码**：切集按短剧行规（每集独立冲突 + 3 秒钩 + 结尾卡点，3000 字一章约出 4-6 集）；分镜带景别/运镜、成片包带转场与按段配乐标——你出的是「手」，不是「脑」
- **成片包管到出片**：配音稿（TTS 友好文本 + 声线 + 估时，配音与画面时长不匹配自动提示）+ 剪辑清单 + **SRT 字幕**（剪映/PR 直接导入）；出片顺序：定妆照 → 出图 → 图生视频 → 配音 → 按清单拼 → 压字幕 → 铺 BGM
- **预告片一键混剪**：从各集钩子/高能分镜混剪 30-60 秒——炸点开场、冲突连切、悬念定格，附金句文案骨架与标注取材来源的分镜表
- **配音合规红线**：只用音色特征描述 + TTS 平台**正版音色库**选型，绝不克隆、不指名模仿任何真人声音；商用发布前确认所选音色的商用授权
- **沿用「只产提示词」哲学**：不接生成模型、零新配置——图像视频模型迭代快、按张按秒计费，编排与专业知识才是我们做的部分，工具你自己挑

详见官网 [功能导览 · 漫剧工坊](https://ynnyh.github.io/jarvis-write/features#漫剧工坊-小说一键改编漫剧)。

## 核心特性

- **正文即界面的写作工作台**：日常写作按「开书 / 写作 / 全书」三区组织；写作区打开就是本章正文，选中段落就地「改这段 / 手改」，读到多处问题可边读边批注、一次性定点改；一条常驻 **AI 窄栏**梳理修改意见后锁情节整章优化或重写，AI 改动一律 **diff 逐条验收**、旧版留快照；章首一张**交稿单**用一句话报告本章自检（校对、与设定有无冲突），要改的一键带进验收流。命令面板 `Ctrl+K` 输章号或动作名直达，全套快捷键桌面端与浏览器通用
- **六步生成流水线**：种子 → 角色动力学 → 世界观 → 情节架构 → 章节蓝图 → 逐章正文（成熟的雪花写作法 Prompt 体系，鸣谢见文末）；生成章节蓝图时**逐章增量生长**，进度实时显示「已生成 N / 共 M 章」，不再对着黑盒批量调用干等
- **章节标题风格与一键批量改名**：生成蓝图前先给全书标题定调——**朴素 / 带钩子 / 悬疑冷峻 / 含蓄诗意**，治「AI 起名个个『惊天逆转！命运终章！』」的标题党毛病；已成书可在大纲页**一键为全书重拟一整批标题**，old→new 逐条预览、勾选、可自改，只换标题、不动剧情，已写正文不会被标失配
- **长程一致性引擎**：时序故事圣经（每条事实绑定生效章节区间，可查"第 N 章时角色状态"）、伏笔四态调度（埋设/强化/回收/弃用，到期自动提醒）、章后自动抽取实体与事实写回圣经
- **逐章生成 + 一致性检查**：定稿后自动与故事圣经比对找矛盾，问题列表交用户拍板，不擅自改稿；被拦下时章首一张说人话的卡给三个明确选择（按矛盾重写 / 改设定 / 忽略继续），不必懂黑话；内置重复用词检测
- **大纲级联更新**：随时改任意一章大纲，系统自动做改动分级（minor 零成本短路）→ 下游影响分析 → 用户勾选后级联重生成；已有正文自动标记失配，大纲全程版本化可回溯
- **润色引擎**：整章或选段风格化润色，**锁定情节事实**（润色前抽事实清单、润色后逐条校验）
- **去 AI 味（双向锚定 + 自愈闭环）**：正向锚——名家 / 预设文风范本（可选余华 / 鲁迅 / 汪曾祺等，或喂自己的范文、从已认可章节提取）+ ✗AI 腔→✓人话 配对反例；检测——9 类套话规则库（含专揪「脑内涟漪 / 仿佛有人在远方呼唤 / 无形的手」式空洞比喻的重罚旁路）+ 4 项句式统计（句长 burstiness / 节拍器句组 / 段落结构 / 长重复）打 AI 味指数；门禁——定稿超标自动定向去味重写、复测收敛、没改好即回退，绝不落更差版本。正向锚铺满续写 / 片段润色 / 整章润色所有入口；名家文风均标注"风格参考·非原作节选"（自撰仿写，不嵌原文）
- **场景节拍 + 文风备忘**：章节蓝图带 3-5 个场景节拍，正文按节拍铺场景不再松散；文风备忘随书自动累积（调性/人物声音/复现意象），注入后续章节，长篇后段不变味；不同任务自动分档采样温度
- **已有书翻新引擎**：旧章节按新逻辑重构——回填节拍、初始化文风备忘、轻度重润（锁情节）/ 重度重写（整章重跑）；中途失败已完成章进度保留，可续跑剩余章节
- **质感看板**：章节地图带主审四维评分与 AI 味指数，哪章该返工一目了然
- **标签化倾向系统**：chips + 自定义输入 + 预设模板，贯穿大纲、正文、润色三个节点，风格/节奏/基调由用户说了算
- **创作偏好档案**：文风 / 禁忌 / 读者定位 / 其他主张结构化沉淀为项目级档案，作为最高优先级约束贯穿所有生成环节；研讨中的主张可一键吸收沉淀，已生成的老书打开即自动从正文反向提炼启用
- **字数守卫与自动拆章**：定稿超标自动压缩重写，严重超标自动拆章（LLM 选断点 + 全表编号顺移 + 圣经/摘要重建），结构改动与正文同事务原子落地，中途崩溃不损坏正文
- **编辑部回显**：主审 / 校对结果留存，生成时的自动修复清单与手动待修清单打开即见，正文一旦改动自动失效，不留过期误导
- **重写前先聊**：重写前与 AI 多轮对话蒸馏出精准修改意见，再据此重写，避免"AI 猜你想要什么"
- **AI 对话真流式打字机**：选段讨论、整章问答、重写研讨的回复**逐字流式蹦出来**（像真人敲键盘），首字未到时原地转圈，聊完自动收敛出修改意见 / 改写建议与档位建议；基于 fetch + ReadableStream 手工解帧（带鉴权），经中转站 / CDN 反代也不被攒着一次性下发
- **全书阅读器**：主题（纸张/牛皮纸/夜间）、字体、字号可调；段落级 AI 问答与润色，选中即问、采纳即替换
- **漫剧工坊（衍生改编）**：把已定稿小说改编成竖屏漫剧拍摄手册——画风方向自己拍板（国漫厚涂 / 日系二次元 / 3D / 水墨 / 赛博 / 真人写实，AI 也可按书荐前三个带理由）→ 美术风格卡 / 角色卡 / 场景卡（画风锚 + 人物锚逐字注入每格分镜，保一致性；角色可出**定妆照**参考图提示词并上传存档，锁脸从文字提升到像素）→ 集数规划（每集开场钩子 + 结尾卡点）→ 单集剧本（对白 / 口播双模式）→ 分镜表 → 三轨绘图提示词（中文六层 / 英文 / 负面词，**按你用的生图站一键粘贴**：单描述框站整段版 / 双框站分开版 / MJ 参数版，手册与 CSV 同规则）→ 成片包（声线选型 + 配音稿 + 剪辑清单 + SRT 字幕，配音走平台正版音色、禁克隆他人声音）→ 预告片一键混剪（高能镜头 + 金句文案，30-60 秒），整集导出 Markdown / CSV / JSON / 成片包 / 字幕，拿去即梦 / 可灵 / MJ / 剪映出片；工作台管线步骤条 + 资产侧栏布局，沿用「只产提示词」哲学，不接生成模型
- **多用户**：JWT 登录 + 邀请码注册 + 每用户独立配置 LLM key + 数据隔离；移动端已适配
- **导出与统计**：整本导出 txt / epub；token 用量统一埋点、实时统计
- **Docker 一键部署**：单容器，前端产物由 FastAPI 托管，数据卷持久化
- **桌面版（Windows）**：安装包开箱即用，免登录单机运行、数据落本机；由 GitHub Actions 自动构建并发布到 Releases

## 快速开始

### 方式一：桌面版安装包（最简单 · Windows）

从 [GitHub Releases](https://github.com/ynnyh/jarvis-write/releases/latest) 下载最新的 `jarvis-write_<版本>_x64-setup.exe`，双击安装即可。免登录单机运行，作品数据存在本机（`%APPDATA%\jarvis-write`），无需部署、无需配置数据库。首次打开后在「模型设置」里填上你自己的 LLM API key 即可开始创作。

### 方式二：Docker（自部署多用户服务）

```bash
git clone https://github.com/ynnyh/jarvis-write.git
cd jarvis-write

# 配置必填环境变量（见下方"配置要点"），然后：
docker compose up --build
```

访问 `http://localhost:8000`（端口可用 `PORT` 环境变量覆盖）。SQLite 数据持久化在 named volume `jarvis_write_data`。

### 方式三：本地开发

```bash
# 后端（首次需建 venv、pip install -r requirements.txt、cp .env.example .env 并配 key）
cd backend && python -m app        # http://127.0.0.1:8000

# 前端（另开终端，/api 代理到 8000）
cd frontend && npm install && npm run dev   # http://localhost:5173
```

详细步骤、冒烟测试与目录结构见 [backend/README.md](backend/README.md)。

## 配置要点

| 配置项 | 说明 |
|---|---|
| `JWT_SECRET` | JWT 签名密钥，**必填**，必须设为随机长串（公网部署否则 token 可被伪造）。`APP_ENV=prod` 下仍用弱默认值将**拒绝启动** |
| `ADMIN_PASSWORD` | 初始管理员密码，**必填**（Docker 下无默认值；代码默认值仅限本地开发） |
| `INVITE_CODE` | 注册邀请码：填对才能注册；**留空则关闭注册** |
| LLM API key | 支持 DeepSeek / OpenAI / Gemini 及任意 OpenAI 兼容中转站。每个账号登录后在**设置页**配自己的 key——可存多套命名配置，一键切换默认（强模型档）/快档（存数据库，推荐）；也可用 `.env` 做兜底 |

完整配置项见 [backend/.env.example](backend/.env.example)。

## 技术栈

- **后端**：Python 3.12 + FastAPI（REST + SSE），SQLAlchemy 2.x + SQLite（可切 Postgres），Pydantic v2
- **LLM 层**：自封适配层（DeepSeek / OpenAI / Gemini，不用 LangChain），任务级模型路由（强模型/快模型分档，各选一套配置），cc-switch 风格多配置管理，瞬时错误自动重试 + 流式聚合兜底（防中转站 CDN 掐断长请求）
- **前端**：React + TypeScript + Vite
- **部署**：单容器 Docker（多阶段构建，前端产物由 FastAPI 托管在 `/app`）
- **桌面版**：Tauri 2 壳 + PyInstaller 冻结后端，GitHub Actions 自动构建 NSIS 安装包并发布到 Releases

## 项目状态与路线图

阶段 0–8 已全部完成：生成流水线与倾向拼装器、逐章生成、长程一致性引擎、大纲级联更新引擎、润色引擎、Web 前端工作台、token 统计与 txt/epub 导出、Docker 部署、多用户与移动端适配。每阶段验收结果与实现偏差见 [docs/05-roadmap.md](docs/05-roadmap.md)。

已知遗留项：

- **逐 token 真流式**：AI 对话（选段 / 整章讨论、重写研讨）已升级为 SSE 逐字真流式打字机，章节蓝图生成也已「逐章增量」上报进度；唯逐章正文生成因需串联多步审校（去味 / 一致性 / 字数守卫）仍走"异步任务 + 进度轮询"，更适合任务化

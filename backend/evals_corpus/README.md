# 确定性轨语料库(evals_corpus)

CI 的「确定性轨」门禁(`python -m app.evals deterministic --dir evals_corpus --target-words 3000`)
就对这个目录跑。**这是回归基线,不是给人看的样本**——改它等于改门槛。

## 这些文件是什么

《破封纪》10 章正文,来自 **official-flash** 这轮正式基线评测
(`evals_out/official-flash-po_feng_ji-20260904-221810.chapters.md`,2026-09-04 22:02,
官方 deepseek-v4-flash)。按 `## 第 N 章` 切成逐章 `.txt`,文件名 `ch001.txt` …
按名排序即章序(跨章指标依赖顺序)。

基线读数:AI 味均值 **2.7** · 章内复读 **0** · 跨章重复句 **6** · 篇幅比 **0.94**。

## 为什么要落成独立文件

原来的评测正文只存在于 `evals_out/*.chapters.md` 与 run JSON 里,而 `evals_out/` 是
**跑评测的产物目录**(不进版本库、随时可被覆盖)。CI 需要一个**稳定的、随代码一起
版本化的**样本,才能回答「这次改动有没有让生成质量变差」——把样本钉在仓库里,
回归检查才有可比性。

## 怎么更新它

只有当**正式基线本身被替换**时才更新,并说明原因(`python -m app.evals run` 出新基线
后,用同样的切分方式重生成)。**不要**为了让 CI 变绿而改这些文件——
那等于把门槛调松,是自欺。

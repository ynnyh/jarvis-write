# 19 核心梗为纲:梗卡 / 作战图 / 追溯与对账(规划与实施记录)

> 2026-09-12 立项。源头是作者的原始诉求:「写第一章时,怎么方便地看到这章的章纲、
> 伏笔、出场人物、结尾钩子,以及这些角色、情节、钩子背后的关联关系,能不能随时
> 点进去追溯;再有个简单场景地图理顺情节进展;不管我怎么安排实际剧情,这些关系
> 都自动帮我建联、纠正——这就是不崩、能改、可控。」
> 后经讨论确立:**小说的核心是核心梗**——梗是入口,兑现循环是留存,边界是生命线;
> 整个系统应以核心梗卡为中心对象组织交互。

## 0. 四条铁律(全案不变)

1. **梗是纲**:梗卡是一等对象;蓝图逐章标「梗兑现」,作战图/对账/体检都是它的投影。
2. **圣经是唯一真相**:图谱/地图/档案是确定性投影,AI 抽取只做补充且必须带证据锚;
   绝不让可视化层变成第二份要维护的状态(两份真相必然漂移)。
3. **点点点**:任何对象两跳内回到原文证据(章/段落锚)。
4. **AI 建联给作者裁决权**:抽取产物可一键否决;作者手写的永远权威。

  行程耗时/势力约束的空间一致性检查),世界模型商用后替换为真模型。不进关键路径。

- **地图化创作沙盒**:作者以角色视角在世界里走 → 触发事件 → 一键「写成第 N 章场景」
  → 回到场景级生成管线。

## 3. 关键设计决策记录

- **梗卡三件套**:高概念(入口)/ 兑现机制(留存)/ 边界禁忌(生命线)。
  光有梗撑不过三十万字;系统要建模的是「梗的可重复兑现」。
- **pending 不拦截注入**:抽取新边 status=pending 只是对账 UI 状态——边本就从真实
  正文抽出,历史行为就是直接进圣经;拦截会静默撤掉安全网。否决 = 删边 + 收口其
  证据事实(本章新立直删,更早的 valid_until=n-1,KnowledgeState 引用先清)。
- **存量为 confirmed**:迁移不翻 pending,否则存量书的关系约束被静默撤掉。
- **作战图是投影**:零新抽取,聚合 Outline/Scene/Premise/Foreshadowing/Entity/
  Relationship/ChapterState.contract;缺数据如实缺省,不填 0 冒充没问题。
- **实体浮卡先行**:Prose 实体高亮 + hover 卡 + CharacterCard.appearance_chapters/
  RelationEvidence 在 v0.40 前后已落地,M2 只补关系区、证据展示与跳章。

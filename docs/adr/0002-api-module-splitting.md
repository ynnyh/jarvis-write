# ADR-0002: API 层大文件按子资源拆分

- 状态：✅ 已采纳
- 日期：2026-08-26
- 决策者：项目维护者

## 背景

随着功能迭代，`app/api/drama.py` 累积到 42KB / 1100 行 / 35 个路由，包含风格卡、角色卡、场景卡、定妆照、集规划、剧本、分镜、提示词、成片包、预告片、导出等多个子资源的全部逻辑。

大文件的问题：
- 认知负荷高——修改一个路由需要在 1000+ 行里定位
- Git 冲突概率高——多人在同一文件不同位置修改容易冲突
- 代码导航困难——IDE 的文件大纲被 35 个函数撑满
- 难以并行开发——不同子资源的改动互相阻塞

## 选项

### 选项 A：保持单文件

- 优点：简单，所有路由在一个文件里一目了然
- 缺点：上述问题持续存在，文件继续膨胀

### 选项 B（采纳）：按子资源拆分为包

- 创建 `app/api/drama/` 目录
- `_common.py`：共享的请求模型、工具函数、imports
- 各子模块：`style.py` / `characters.py` / `episodes.py` / `shots.py` / `trailer.py` / `export.py`
- `__init__.py`：定义主路由（前缀 + 鉴权依赖），聚合所有子路由，包含 meta 准入信息路由
- 子路由不加前缀，通过 `router.include_router()` 自动继承主路由的前缀和鉴权依赖
- 对外接口不变：`from app.api.drama import router as drama_router`

## 决策

采纳选项 B：按子资源拆分为包。

理由：
1. 对外接口不变——`main.py` 的 import 无需修改，零迁移成本
2. 每个子模块职责单一——修改风格卡只动 `style.py`，修改分镜只动 `shots.py`
3. 共享逻辑收敛到 `_common.py`——避免各模块重复定义请求模型和工具函数
4. 子路由通过 `include_router` 继承前缀和鉴权——避免路径重复拼接和鉴权依赖遗漏
5. 测试全量通过——37 个 drama 相关测试全部通过，验证拆分无损

## 后果

### 正面
- 每个文件最大约 9KB（characters.py），远小于原来的 42KB
- 修改特定子资源时只需关注对应文件，认知负荷大幅降低
- Git 冲突概率降低，不同子资源的改动可以并行
- 代码导航更清晰，IDE 大纲只显示当前子资源的函数

### 负面
- 新增一个目录层级，从 `app/api/drama.py` 变成 `app/api/drama/__init__.py` + 多个子模块
- 共享逻辑需要显式从 `_common.py` import，比单文件多一步
- 新增子资源时需要创建新文件并在 `__init__.py` 里 include_router

### 后续
- 其他大文件（如 `api/clips.py` 24KB、`api/birthday.py` 24KB、`engines/pipeline/chapter.py` 43KB）可按同样模式拆分
- 拆分原则：按子资源 / 按职责拆分，共享逻辑放 `_common.py`，对外接口保持不变

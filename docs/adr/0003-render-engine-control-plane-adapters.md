# ADR-0003: 出片引擎——控制面闭环,执行面接入(轻量/完整双档)

- 状态:✅ 已采纳
- 日期:2026-08-28
- 决策者:项目维护者

## 背景

jarvis-write 的四条出片线(漫剧/宣传片/情绪短片/生日短片)一直遵循「只产提示词」哲学:
剧本、分镜、三轨提示词在本站做,出图/出视频在站外工具(即梦/可灵/剪映)手工完成。
这条路线把上游创作层做深了,但下游执行全靠人肉:逐格粘贴提示词、去平台等结果、
下载、回站里手工记进度。调研开源流水线(MoneyPrinterTurbo/StoryFlicks/Toonflow 等)与
执行面平台(autodl.art ComfyUI 工作流 API / 火山 Seedance / 百炼)后,需要决定工坊
往下游延伸多少。

## 选项

### 选项 A:全自研闭环(自托管视频模型 + TTS + FFmpeg 合成全在本站)

- 优点:零边际成本、完全可控
- 缺点:模型迭代太快,自托管等于永远追 checkpoint;GPU 成本与部署维护对单人项目是无底洞;
  平台们(即梦故事模式/可灵首尾帧)正在把「生成」产品化,在其最快赛道上赛跑必输

### 选项 B:维持纯导出(复制提示词,不碰执行)

- 优点:零工作量
- 缺点:人肉粘贴摩擦大,且工坊对成片质量没有反馈回路,分镜层无法据出片效果迭代

### 选项 C(采纳):控制面闭环 + 执行面接入

- 工坊闭环「控制面」:分镜/资产/衔接协议/QC 回路——这是护城河,任何平台都不替你做
- 生成本体外包给「执行面」,做成可切换 adapter;首个实现选 autodl.art 的
  ComfyUI 工作流 API(国内直连、¥0.02/秒、工作流级可控、文件参数支持 base64)
- 功能上分**两档模式**,用户自选(项目级开关 `render_mode`):
  - **轻量档**:文+图 → 视频。有静帧走首尾帧工作流,无静帧走文生视频;出片/重 roll/版本
    筛选在镜头卡片完成。宣传/情绪/生日等线默认此档
  - **完整档**:对白链(TTS→对口型)+ 首尾帧自动接力 + 一键合成。**分期点亮**,
    未点亮模块前端显示「未启用」占位;两档共用同一份数据,切换不丢任何东西
- 出片单位:漫剧=格(drama_shots),情绪短片=段(clip_shoots);引擎核心线无关,
  「提交参数构造器」由各线自供(漫剧 video.py / 情绪 render_input.py),
  共用件(运镜词表/视频负面词/时长与分辨率口径)下沉 `media/video.py`——
  遵守「线间禁互引,共用件进 media」的既有约定

## 决策

采纳选项 C。首期落地轻量档全量 + 完整档占位,漫剧与情绪短片两条线接入。

配套决策:

1. **渲染草片落盘** `uploads/render/r<task_id>.mp4`:渲染平台结果 URL 短效,不当场下载
   就永远丢了。这与「视频刻意不收上传、clip_ref 只记指针」的旧决策不矛盾——旧决策针对
   **用户上传**的成片(几十 MB 吃配额);渲染产物是引擎自己的输出、必须落盘才存在,
   指针语义不变(clip_ref/result_link 照旧指向"成片在哪",只是值可以是站内文件名)
2. **重 roll 攒版本**:每次出片一行 `render_tasks`,「哪版当成片」由各线指针字段决定,
   打勾(done_video/done)永远留给人工
3. **提示词口径与 video.py 同源**:出片 API 的 prompt 复用运动轨/视频负面词/时长夹取,
   与「一键粘贴」同一套规则,不另写一份(防两路口径分叉)
4. **零新增后端依赖**:HTTP 用既有 httpx;一期无抽帧需求,不引入 ffmpeg
5. **不自建**:自托管扩散模型、自训 LoRA 服务、逆向闭源平台接口,都不做

## 后果

### 正面
- 「贴提示词出站等结果」变成镜头卡片上一个按钮,执行摩擦大幅下降
- 执行面可切换:平台涨价/退步时换 workflow 或换 adapter,控制面资产(分镜/资产/进度)无损
- 双档设计让不同用户各取所需:要省事的用轻量档,要全自动的等完整档点亮
- 出片结果(版本历史+指针)留在工坊内,QC 回路成立,分镜层可以据出片效果迭代

### 负面
- 依赖外部平台的可用性与计费(当前 ¥0.02/秒;凌晨半价);token 泄露风险靠加密落库 +
  接口打码 + SSRF 校验缓解
- 渲染产物落盘引入存储增长(15s 768p 约几 MB/版);重 roll 多了需要用户自行清理
  (删项目/删短片时级联清理已覆盖)

### 需注意
- 基线 Alembic 迁移随新表原位更新(render_configs/render_tasks/projects.render_mode),
  存量库由 create_all + migrate.py 兜底补齐
- 完整档的点亮顺序(后续 ADR/CHANGELOG 跟踪):对白链(indextts2→对口型工作流)→
  首尾帧自动接力(FFmpeg 抽末帧)→ 一键合成 → 宣传/生日线挂按钮 → 批量/夜间队列

# 33 · 文风复读升级:身体反应套话(取证 + 判据 + 三件套)

> 状态:已落地(v0.58.0)
> 日期:2026-10-17
> 缘起:作者实测反馈——「AI 经常在这一本小说里,甚至每章都写,他紧紧攥起拳头,指甲渗进肉里,
> 流出血。后面又写伤还没恢复,他又捏住拳头,指甲渗入肉里,又流血了,这玩意看着不难受吗」;
> 要求「不要限制过度,但也不能无痛呻吟」。作者说「我写了好多本小说都有类似的问题」。

---

## 1. 取证(线上库,只回计数,不导出正文)

对生产库 1868 章已定稿正文做正则统计(脚本在容器内跑,只输出计数):

| 族 | 总命中 | 出现章数 | 单章 ≥2 次章数 |
|---|---|---|---|
| 手部痛感(攥/捏拳 · 指甲掐肉 · 掌心渗血) | 159 | 102 | 29 |
| 咬唇 / 咬牙 | 195 | 180 | 13 |
| 眼眶泛红 / 泪水打转 | 40 | 38 | 2 |
| 呼吸一滞 / 深吸气 | 79 | 74 | 4 |
| 喉结滚动 | 19 | 16 | 1 |
| 心跳 / 心脏猛跳 | 10 | 9 | 1 |

按书分布(手部痛感族):项目 19(1713 章)42 章 2.5%、项目 10(30 章)**16 章 53%**、
项目 4(19 章)9 章 47%、项目 30(33 章)9 章 27%、项目 9(11 章)7 章 64%。
相邻章连发:手部痛感 **36 处**、咬唇 20 处。

**结论**:作者说的「甚至每章都写」是真的,而且**按书差异极大**——所以判据必须是
「这一章里重复了」(局部密度),不是「出现了」(全局词表)。全局词表在这个语料上要么
罚不到(大书 2.5%),要么把整本书都判红(53% 那本)。

## 2. 为什么现有四道防线都没接住

| 防线 | 现状 | 为什么漏 |
|---|---|---|
| 静态规则表(`_RULES`,10 类) | 管万能神态 / 空洞比喻 / 翻译腔 | **没有「身体动作与生理反应」这一类**,攥拳掐肉一条规则都不匹配 |
| 跨章字面查重(`repetition.avoid_block`) | 句子级:逐字一致 + ≥8 字 + ≥2 次;词组级:4/5/6 字 n-gram + ≥3 次 | 用户例子是**换词复用**(攥→捏、渗进→渗入),逐字不同 → 漏;七字短语超 n-gram 长度 → 漏 |
| 生成端疲劳词表(`fatigue_block`) | 从 `_RULES` 类别聚合 | 继承第一行的盲区 |
| 自愈闭环(`deai_self_heal`) | 整章级:总分超门槛才定向重写 | 单章内同一动作重复两次对**总分**贡献极小 → 永远不触发 |

另注:`_DEAI_RULES` 与 `DEAI_REWRITE_PROMPT` 里**早就写着**「身体化描写全篇保留一两处最强的高峰即可」
——口径一直是对的,缺的是**检测**与**跨章记忆**,不是提示词。

## 3. 判据(频次维度,不是禁词表)

`ai_flavor.py` 新增 `_BODY_REACTIONS`(族 + 单章阈值 + 正则)与两条语义:

1. **按句归并**:同一句里命中多个子模式只算**一次**。「他攥紧拳头,指甲渗进肉里,流出血来」
   是**一次**拿身体反应代替情绪,不是三次(按子模式数会数成三处,本轮实测踩到过,已回归测试)。
2. **只计超出的那几次**:族阈值 = 手部痛感 2、咬唇咬牙 3、眼眶泛红 2、喉结 2、心跳 2、呼吸 3。
   第一次永远不算——单独一次不罚,这是「别限制过度」的落点。
   命中落在对白里按既有 `_DIALOGUE_DISCOUNT` 打折。

## 4. 三件套(检测 → 预防 → 定点修复)

- **检测**:`ai_flavor_report` 新增类别「身体反应复读」+ `metrics["body_reactions"]`
  (按族计数,人话摘要里直接显示「身体反应复读(攥拳掐肉/掌心渗血×2)」)。权重 1.5(与
  「空洞比喻堆砌」同档:比普通套话重,但不至于一击致命)。
- **生成端预防**:`polisher.body_reaction_note` —— 最近几章里 **≥2 章**用过同一族,就写进
  `fatigue_block`(最多 3 族)。措辞刻意**不用「禁止」**:禁词会把写法逼成更空的「他握了握拳」,
  这里要的是换载体(具体行为 / 环境 / 对话 / 别人的反应)。身体反应那一类从「严禁再犯」的
  类别聚合里摘出去了——同一个毛病两块话说两样,模型只会照更硬的那句办。
- **段落级定点修复**:`polisher.deai_heal_repeats` —— 只重写**含多余命中的那几段**(最多 4 段、
  单段 ≤1500 字),喂 `DEAI_SEGMENT_PROMPT`,要求按原顺序回 JSON 段数组。安全阀与
  `deai_self_heal` 同款:没有重复时**零成本短路不调 LLM**;段数对不上 / 空段 / 篇幅越界
  (0.75–1.25)/ 未降分 / 统计判据倒退 / 过度矫正,一律丢弃本轮。挂在定稿收尾
  (`chapter_finalize`)里 `deai_self_heal` 之后,分数变化透传 `review.deai_repeats`。

## 5. 另一半:伤情连续性(不是文风问题)

「伤还没好又攥拳流血」是**事实层**矛盾。好消息是零件都在:抽取词表里本来就有 `state`
(「受伤/痊愈」写在抽取规则第 1 条),`state` 不在 `RESOURCE_FACT_TYPES` 里,会照常进硬约束;
门禁也有 `type=state` 的问题类型;桥段台账(`motifs`)甚至专门点名「自残式动作」。
这一版做的两处口径补强(加在抽取与门禁的 prompt 里,加一句,不改结构):

- 受伤事实**必须带部位与状态**(如「右手掌被刀划开、未愈、影响握持」),痊愈时 `replaces`
  必须逐字抄那条伤势原文——伤势留在账上,后面才不会写出「伤还没好又攥拳流血」;
- 桥段台账的例子里补上「身体反应套话(攥拳掐肉、掌心渗血、咬唇、喉结滚动、眼眶泛红)」,
  让跨章台账能吃到这一类(它此前只举了「扎手、刺胸」)。

另外,门禁的「人物状态」维度补了一句**伤势对账**:账本里未愈的伤(带部位与状态)在本章是否被
无代价地使用(伤在右手却攥拳发力、缠着绷带却利落地握持),或同一处伤时好时坏、凭空痊愈、
反复流血——要求报的时候点明「哪一句」与「哪条伤势」冲突,不许只说"描写不一致"。

**没做(如实记)**:① 作者侧的「本书意象白名单」——有意复沓 / 口头禅目前只能靠阈值和
「第一次不算」兜,下一轮做;② 伤情的**确定性**比对仍是 LLM 判定(取证已确认账本里
有 48 条伤情 state 事实、其中 28 条带部位,零件齐)——纯规则会把「他攥拳时牵动伤口」
这种**正确**写法误报,所以这一版只把要求写进门禁维度,不写死规则;③ 界面上的
`deai_repeats` 徽标(数据已在载荷里,前端未展示);④ 族的阈值**不在管理端可调**——那套
权重热更只覆盖 `_RULES` 的类别(形状不同),这一版阈值按取证标定、写在代码里。

**已有书怎么办**:检测口径一改,`/api/overview` 的逐章 `ai_flavor_score` 与章节体检
(`POST /api/polish/check-ai-flavor`)会自动带上这一类——旧书不必重写也能**看见**哪些章
在用这套写法(体检报告里会显示「身体反应复读(攥拳掐肉/掌心渗血×2)」);要**改掉**已写的
章节,走既有的翻新 / 定向重写通道。

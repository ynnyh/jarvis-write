## 2. 包设计（Part 1：补包）

### 2.0 设计原则

1. **包 = 口径的可版本化载体**；引擎读包决定分支，**包不改变"不挂载就不生效"**的现状语义。
2. **同义包合并 scope，不重写**：三条线都要的工艺，一个包打通，不各写一份（延续 `media/` 精神）。
3. **工艺进包，风格留在选择器**：画风/情绪/题材仍走既有选择器（docs/21 §1.1 已定分工）。
4. **每个包 ≤ 12 条目 / 单条 ≤ 600 字**（`normalize_entries:196` 的既有约束）。

### 3.2 包控开关的统一写法（三线一致，照抄 anime）

```python
# engines/<line>/common.py
def pack_on(db: Session, pack_key: str, node: str, scope: str) -> bool:
    """某工艺包当前是否生效。关掉 = 走今天的行为(零回归的唯一保证)。"""
    return any(p.pack_key == pack_key
               for p in active_packs(db, scope=scope, node=node))
```
调用侧一律 `if pack_on(...): 增强路径 else: 现有路径`，**不许把开关做成"只增强不回退"**。

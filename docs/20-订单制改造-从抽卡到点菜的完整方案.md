# 20 订单制改造:从抽卡到点菜的完整方案(规划与实施记录)

> **实施状态(2026-09-16,首批)**:一~三期 + 灵感字段锁已落地(§12 一/二/三期
> 与 §3 字段锁部分,含 §14 全部防线),「终止改向」(§9)与体检退场提醒后置(见
> 文末「首批落地差异」)。新增测试:backend `tests/test_order_system.py`(10 例)、
> frontend `chapterOrderCard.test.tsx`(4 例)。

> 2026-09-16 立项。源头是作者的原始诉求:「小说生成操作过于抽卡了,生成的内容很大一部分
> 依赖模型的能力,但是咱们想要的内容,太黑盒了。」并明确两点:①写前要能**确认**本章人物
> 关系(不是只读展示);②全书要能查看全部人物关系。
>
> 经全链路走查(灵感 → 确认墙 → 点火 → 蓝图 → 单章生成)确认:抽卡感的根因不是展示形式,
> 而是**每一层都缺「订单」**——想要什么没在生成前写成可校验的契约,成品也没有对着契约验收。
> 本案把整条创作链改造成订单制:每层都是「草稿 → 人确认成订单 → 下层照单生成 → 成品对账
> → 回写/定向重做」的循环,锁定机制贯穿全链。

## 0. 四条铁律(全案不变)

1. **订单先行**:任何生成动作,注入的必须是「人确认过的订单」;没确认就按上一层产物降级
   (蓝图行即订单),但系统永远知道并标明当前跑在哪个粒度——绝不静默自由发挥。
2. **锁定即宪法**:被锁定的产物,任何重摇/级联/批量操作不得触碰;要动,必须显式解锁。
   重摇范围从「全部」缩到「没锁且不满意的部分」,这是点菜与抽卡的本质区别。
3. **成品对订单负责**:每次生成都产出「订单 vs 成品」的对账,偏差逐条摆到作者面前裁决;
   重写带偏差清单,做靶向手术,不做无差别盲摇。
4. **订单是意图,圣经是事实,二者不得混写**(沿 19 号铁律 2):订单可以因成品更好而被作者
   改判(接受偏差=改订单),但事实永远由抽取+作者确认写入圣经;可视化与对账都是投影。

## 1. 诊断:骰子摇在哪

| 环节 | 现有控制 | 骰子位置 |
|---|---|---|
| 灵感 | 三条款(AI 方案/指令改/对话捏)+ 卡阵选卡 | 摇整卡:方案间不可字段级拼装,重摇=全部重来 |
| 确认墙→点火 | 确认概念/题材/倾向/书名/篇幅五个元数据 | **最大黑盒**:确认 5 个字段,一枪摇出架构+全书蓝图(几百个决定),1→N 爆炸零话语权 |
| 蓝图 | 逐章内联编辑、大改分级、级联范围勾选 | 事后救火;无锁定概念,级联波及不可豁免满意的章 |
| 单章 | 蓝图行+场景卡+作战图+门禁+评分 | 控制密度最高但**无订单验收**:成品偏离「想要」没人报警,不满意只能盲摇 |

## 2. 核心抽象:订单金字塔与锁

### 2.1 订单金字塔

```
概念订单 → 架构订单 → 骨架订单(段/卷) → 章纲订单(蓝图行) → 章节订单(写作前确认单) → 成品
   └──────── 每层:AI 产草稿 → 人确认 → 下层照单生成 → 对账验收 → 回写/定向重做 ────────┘
```

### 2.2 数据模型

- **`chapter_orders` 新表**:`(project_id, chapter_number)` 唯一;payload JSON 六单(§5);
  `status: draft|confirmed`;`version` 递增,历史版本存 payload 历史(轻量,参照
  ChapterState.contract「一章一份当前契约」哲学,版本留痕不建全表)。
- **`arcs` 新表**(段级骨架):`(project_id, seq)` 唯一;title/goal/core_conflict/
  start_state/end_state/chapter_from/chapter_to;`status: draft|confirmed`;`locked`。
- **锁字段**:`outlines.locked`(章纲锁)、`arcs.locked`(段锁)、
  `project.concept_locks` JSON(概念字段锁 map)、`project.arch_locks` JSON(架构块锁 map)。
- **Job 表补三列**:`parent_job_id`(队列父任务)、`project_id`、`chapter_number`
  (服务端解析 kind 后入库,前端不再正则猜)。

### 2.3 锁语义(全链统一,一处定义四处消费)

| 锁 | 短路哪些操作 |
|---|---|
| 概念字段锁 | 字段级重摇跳过该字段(已锁字段作为约束喂给重摇 prompt) |
| 架构块锁 | 架构整体重生成/研讨后重摇,跳过该块 |
| 段锁 | 段内铺章重摇跳过该段 |
| 章纲锁 | 蓝图批量重铺、影响分析级联、指令改批量——一律短路;级联勾选 UI 显示「已锁,不解锁不级联」 |

章节订单没有锁概念(它本来就是每章最新的意图),只有确认态;未确认订单时队列行为见 §10。

## 3. 灵感层:字段级摇/锁/拼

- 概念六字段逐字段「摇 / 锁 / 手填」:摇单字段时,已锁字段作为硬约束进 prompt
  (换了主角就别再摇出无关的世界观)。
- 多方案**字段拼装**:摇出的 N 个方案不再是整卡二选一——字段格子级「取这个」,
  从方案 A 拿 logline、方案 B 拿对手戏,拼出混合卡即草稿。
- 三条款与 GachaPicker 舞台全保留;改的是**选择粒度**:卡阵翻到一半可以拆卡。

## 4. 点火改造:两段式确认墙(消灭最大黑盒跳跃)

### 4.1 架构确认墙

雪花四步产出后**不直接铺蓝图**,先过架构墙:四块卡片墙(核心种子/角色动力学/世界观/
冲突骨架),逐块「确认 / 重摇 / 手编 / 锁」。架构研讨聊天保留,蒸馏出的修订要求
**只重摇受影响的块**(研讨结论→块级映射)。

### 4.2 骨架先行

架构墙全绿 → 生成**段级骨架**:按篇幅自动分段(60 章 → 6 段 × 10 章,段数可调),
每段产「段名 / 段目标 / 核心冲突 / 起止状态(进段时主角是什么,出段时是什么)」,
过骨架墙:逐段改 / 重摇 / 锁。

### 4.3 段内铺章

逐段铺章纲(现有 CHUNK_SIZE=20 分块落库+版本逻辑降为段内复用),铺完一段亮一段,
骨架墙变进度墙。用户在「每 10-20 章讲什么」这一层获得完整话语权,再谈每章。

### 4.4 信任模式

确认是权利不是门槛:每面墙都有「全自动放行」开关,老手可一口气跑完
架构→骨架→铺章。默认逐墙确认,新手被保护,熟手不被打断。

### 4.5 存量书直通车

老书(已有蓝图)跳过骨架层照常写作;提供一键「从蓝图反推骨架」(LLM 归纳,产物
同样过骨架墙确认),反推后骨架锁/级联语义即刻生效。

## 5. 章节订单:写前确认单(作战图从纯读投影升级为订单编辑器)

### 5.1 六单

| 单 | 内容 | 预填来源 |
|---|---|---|
| 人物进出单 | 新登场(名+为何此时入场)/ 在场(带本章有效关系,可增删)/ 退场(名+方式:死别/远行/暂别+须收的线) | 大纲 characters_involved + `_appearance_chapters` 首末章推断 |
| 关系变动单 | 每条「谁—谁:变化前→变化后(触发事件)」 | 相邻章纲/段目标;确认后成为抽取对照 |
| 节拍单 | 3-5 拍,每拍一句「这拍砸什么」 | 大纲 beats 细化 |
| 钩子单 | 承上(上章契约未回收钩子,可标「必须回收」)+ 启下(本章末留什么钩) | 章末契约 prev_threads |
| 伏笔单 | 本章埋/强化/收 | 伏笔调度自动带出到期项,可加 |
| 场景序 | 场景卡序列,可拖排序 | 场景卡(已有) |

头部「**按单生成**」按钮 = 六单确认入库(status=confirmed)并作为生成依据。

### 5.2 注入与降级

- 已确认订单 → `chapter_compose` 注入订单全文,替代蓝图行「本章简述」粒度;
- 未确认 → 按蓝图行生成(现状行为);生成结果卡标明「按订单/按蓝图行」。

### 5.3 订单版本

每次「按单生成」存版本;重生成时 diff 上一版订单,「订单变了什么」在结果卡可见——
作者改了主意还是模型没照做,一眼可辨。

## 6. 写后验收:全维对账 + 定向重写

### 6.1 对账维度

| 维度 | 订单侧 | 成品侧(数据来源) | 偏差类型 |
|---|---|---|---|
| 人物 | 进出单 | 抽取实体/事实(facts.source_chapter) | 该来没来 / 不请自来 / 该退没退 |
| 关系 | 变动单 | pending 关系边(M3 已有) | 该变没变 / 变了没报 |
| 节拍 | 节拍单 | 章后新增 beat 判定(挂 chapter_finalize 链路,与契约提取同批) | 该砸没砸 / 砸错方向 |
| 钩子 | 钩子单 | 章末契约 threads(已有) | 承上没收 / 启下没留 |
| 伏笔 | 伏笔单 | 伏笔变动记账(已有) | 埋收错位 |

### 6.2 分级与裁决

- **全对** → 一行摘要(沿 ReconciliationBlock「不占地方」哲学);
- **偏差** → 逐条裁决:接受(改订单=实际,写回圣经)/ 打回(进定向重写)/ 忽略(记一笔);
- **失败**(系统性没照单) → 建议整章重写,重写 prompt 自动携带完整偏差清单。

### 6.3 定向重写

偏差清单直接喂现有带批注重写链路(ReworkDialog/AnnotatedReviseCard):「不满意的点」
从人肉批注升级为机器对账产物——盲摇变靶向手术。

## 7. 全书人物关系(书级视图)

### 7.1 关系图谱升级(GraphBoard)

- 节点:近期出场密度→亮度/大小;retired→灰显+退场章角标;
- 边:pending 虚线与滑块时点标签(已有);新增「计划层」开关——叠加下一章订单的
  关系变动单,虚线预览边(「将反目」);
- 布局仍手写 SVG,不引图库(沿 19 号投影哲学)。

### 7.2 人物在场带(PlotMapBoard 同款语言)

- 每角色一行,横带=出场区间(`_appearance_chapters`),首秀点/退场点标记;
- **失踪检测**:角色满足「有未闭合关系边 或 身挂未收伏笔 或 后续大纲仍涉及」
  且超过 N 章(可配,默认 30)未出场 → 黄带警示。人物写丢是长篇最经典的崩法,
  这条带直接回答「谁在场、谁下场、谁失踪」。

### 7.3 人物卡补全(EntityCard)

首秀章 / 最近出场 / 出场章数 / 身上伏笔 / 关系史(带证据章跳转,M2 基础上补齐)。

### 7.4 退场调度

- retired 不再纯手动:体检(HealthBoard)新增「人物去向」区——长期未出场且线已收
  → 建议安排下场;已 retired 又被抽取出场 → 报警(标记与事实冲突);
- 退场方式进人物卡(死别/远行/暂别),暂别可回归。

## 8. 任务中心:按书分组 + 队列树 + 章内流水线点

- Job 补 parent_job_id/project_id/chapter_number(§2.2);
- 任务中心抽屉:按书分组;连写队列父行 + 进度「N/M」+ 可折叠子行(缩进,不画线);
- 章状态卡加**流水线点**:`生成✓ 评分✓ 校对● 润色○ 同步○`(chips 语言同 StepBar),
  点按跳对应卡(ReviewCard/ProofreadCard/…);
- LiveDock 定位不变(盯单任务的驾驶舱,见 §9),桌面与移动同一套结构。

## 9. 生成中驾驶

- 「终止」拆两键:**丢弃 / 改向**——改向 = 带一句指令从断点续写
  (continuation/rewrite_session 基础),LiveDock 加改向输入框;
- 改向指令自动留存为本章订单的「自由指令」字段,下次生成仍生效,直到作者删除;
- 生成中从旁观(看它写)升级为驾驶(看着不对立刻掰)。

## 10. 连写队列与级联的订单语义

- 严格连写(queue_require_approved)新增项目开关:「队列遇未确认订单:
  **暂停等确认**(默认)/ 按蓝图行直写」——全自动党与点菜党各得其所;
- 级联:影响分析照旧;执行遇锁定章**短路**,结果列明「N 章因锁定跳过」;
  级联重写后的章,其章节订单自动标「待复核」(大纲变了,订单可能过期);
- 蓝图批量重铺:锁定章整章跳过,重铺产物不含它。

## 11. 存量兼容

- 无 arcs / arcs 为空 → 直通蓝图(§4.5 反推可选);
- 无章节订单 → 按蓝图行生成(现状),对账按蓝图行粒度(简述+人物+节拍字段);
- 旧 Job 无父号 → 平铺展示(现状),新任务起有树;
- 锁默认全部未锁 → 存量书行为零变化。

## 12. 施工顺序(每期交付都是完整可用态)

| 期 | 内容 | 交付判据 |
|---|---|---|
| 一期 订单制核心 | chapter_orders + 作战图订单编辑 + 按单生成 + 全维对账 + 定向重写 | 「写一章」从抽卡变点菜 |
| 二期 锁定+两段式点火 | 四类锁 + 级联短路 + 架构墙 + 骨架墙 + 段内铺章 + 信任模式 | 「开一本书」从抽卡变点菜 |
| 三期 书级视图 | 图谱升级 + 在场带 + 退场调度 + 任务中心分组 | 「全局」看得见秩序 |
| 四期 入口与驾驶 | 灵感字段级摇/锁/拼 + 终止改向 | 「入口」顺手,「过程」可控 |

一期先行理由:价值核心且不依赖二期;二期依赖的锁定字段在一期表结构里预留。

## 13. 验收指标(怎么证明不抽卡了)

- **章重摇率**:同章按单生成后打回次数 / 总生成次数,较基线显著下降;
- **对账闭环率**:偏差条目被裁决(接受/打回/忽略)的占比;
- **锁定保护命中率**:级联跳过锁定章的次数(锁在被用 = 活机制);
- **骨架返工率**:铺章后段级重摇次数(骨架墙质量的反向指标);
- 观测口径对齐 docs/17 生成质量线上观测方案。

## 14. 影响面与防线(对现有生成过程的逐一确认)

> 2026-09-16 全链路走查结论:本方案**加法为主、改行为为辅**。真正触碰现有行为的
> 只有 10 个点,全部有成熟防御先例可循;其余均为新增表/字段/端点/卡片,存量路径
> 默认走降级分支,字节级不变。

### 14.1 逐期影响清单

**一期(章节订单 + 对账)——生成主链路只有 2 个真实触碰点**

| # | 触碰点 | 风险 | 防线 |
|---|---|---|---|
| 1 | 提示词组装注入订单(`chapter_compose.py::_draft_prompt/_finalize_prompt`) | 订单与蓝图行重复注入 → prompt 膨胀、两个「本章简述」指令打架;订单过长挤压一致性块 | 订单**替换**模板槽位(summary/beats/characters 的渲染位),不是追加;payload 设长度上限,超限截断+告警;未确认订单走原路径,prompt 字节级不变 |
| 2 | 章后链路加节拍判定(`chapter_maintenance.py::apply_chapter_tail`) | 每多一次 LLM 调用多一个失败点 | 沿本链既有纪律:失败降级为「节拍未判定」advisory issue(同 extract 降级落 `source=extract` 问题的先例),绝不阻塞 finalize;存量已写章不回溯判定 |

纯加法零风险项:chapter_orders 表与确认 API(新)、对账扩展(纯读投影)、定向重写(复用 Rework 带批注重写,偏差清单只是批注的机器化来源)。

**二期(锁定 + 两段式点火)——最重的一期,3 个触碰点**

| # | 触碰点 | 风险 | 防线 |
|---|---|---|---|
| 3 | 级联短路锁定章(`cascade/differ.py` + outline 影响分析) | 锁定章的 `is_stale` 永远亮着,用户困惑;下游按锁定旧版重生成,语义正确但不可见 | 锁定章失配标独立文案「已锁定·大纲已变」,不进「建议重写」清单;级联结果列明跳过章;解锁自动重跑影响分析 |
| 4 | 蓝图批量重铺跳过锁定章(OutlinePanel「覆盖全部蓝图」) | 若重铺是删全量重建语义,锁定章会被删——违反铁律 2 | 重铺实现必须为 upsert:非锁定章替换、锁定章原样保留;验收测试:锁 3 章重铺 60 章,断言锁定章 content_hash 不变 |
| 5 | 点火插墙(useOnboarding reattach 硬编码 arch→bp 接力 + setup_state) | 断线重连落在错误的墙上;新 job kind 无标签 | setup_state 枚举向后兼容(parseStep 已有历史取值先例);新 kind `skeleton-`/`pave-` 进 jobLabel 映射;**信任模式(全自动)与今日单枪完全同链路**——这是随时能回到旧行为的逃生门 |

**三期(Job 列 + 任务分组 + 书级视图)——2 个触碰点**

| # | 触碰点 | 风险 | 防线 |
|---|---|---|---|

### 14.2 三条全局纪律(不满足不合入)

1. **存量路径的机器证明**:「无订单 / 无锁 / 无骨架」路径的现有 pytest 全集保持全绿、
   断言不改——这是「存量行为零变化」的测试证据;新增行为各自带单测,CI 全绿才合入。
2. **幂等迁移**:全部走 migrate.py `_column_exists` 模式,老库零重建;部署后
   `curl /api/version` + 冒烟(开一本测试书走完点火 → 写一章 → 过一遍章后链路)。
3. **功能开关兜底**:点火两段式、队列遇单暂停做成项目级开关,默认值 = 旧行为
   (单枪直铺 / 按蓝图行直写);线上异常可即时切回,不用回滚代码。

### 14.3 结论

一期动刀最浅(2 个触碰点且都有先例:模板槽位替换、降级落 issue),先做一期风险最低;
二期最重(级联/重铺语义),按 14.1 #3/#4 的验收测试把关;三、四期靠字段兼容与独立
kind 隔离。按上述纪律执行,现有交互(正文即界面 / 双轨编辑 / 门禁 / 连写 / LiveDock)
不会被破坏。

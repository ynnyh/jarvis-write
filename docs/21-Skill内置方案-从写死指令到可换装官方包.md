## 0. 一句话结论

**skill 不是第 17 种「内置风格」——风格你早就能选（文风胶囊/画像、画风 14 档、动画类型六选）；skill 是「你选的风格能不能稳定做出来的手艺」，它以包的形式挂在风格选择点和生成链三个工序上（出点子 → 分镜/正文 → 渲染提示词），可开关、可改、可版本回退。**
动漫线「提示词长、出片差」的病根已确诊：**动漫线在用「写小说的口径」渲染视频提示词，而漫剧线早已用上正确工艺（一格一卡 + 首帧图生视频 + 负面词轨）——正确答案其实已经在这个项目里，只是没有推广**。第一个官方 Skill 包，就是把漫剧线验证过的工艺包装进动漫线，同时吸收 awesome-seedance 的实证方法论。

## 1. 先回答：skill 融进来到底长什么样

### 1.1 skill 与风格的关系

| | 风格（你要的味道） | skill（把味道做出来的手艺） |
|---|---|---|
| 例子 | 「温情治愈」「日漫赛璐璐」「余华式平匀」「爽文节奏」 | 「一镜只安排一个主动作」「对白不直说情绪」「钩子在第几秒落」 |
| 现状 | **已有承载**：小说=16 文风胶囊+六维画像+手法卡；动漫=6 类型库+14 画风档；漫剧=画风卡 | **散落在代码里，你改不了一个字** |
| 选择入口 | 各线已有的选择器 | 本方案新增：挂在同一选择点上的「创作 Skill 包」，选风格时自动带上对应包 |

**所以「我想选择什么样的风格，你能使用对应的 skill 吗」的答案是：能，而且选择动作不变**——你照旧选风格/类型/画风，系统按你的选择自动挂载对应的工艺包；包的内容你看得见、改得了、关得掉。风格负责「像什么」，skill 负责「成不成」。

### 1.2 挂点：skill 在生成链的三个工序生效

```
出点子 ──────→ 分镜 / 正文生成 ──────→ 渲染最终提示词 ──────→ 你贴进视频/绘图模型
  │                  │                        │
钩子库包          功底包(节奏/景别/         渲染工艺包(镜头卡格式/
(点子按钩子       潜台词/节拍约束注入       身份锁链路/排除清单/
类型学出卡)       生成 prompt)             字数口径)←动漫线痛点在这
```

### 1.3 四条线端到端走查（你每一步看到什么）

**小说线**：你在文风卡选「爽文」→ 自动挂载《爽感节奏包》→ 正文草稿/定稿 prompt 里出现包内条目（章末钩子三型、每 N 字一个情绪节点、憋-放配比）→ 生成后对账页逐条核对「钩子兑现了吗、节拍落了吗」→ 不满意带话重出，包条目跟着你的话微调。手法卡是你已有的私人包，升级并入同一体系。

**动漫线**：你选类型（如悬疑反转）+ 画风 → 分镜生成时挂《分镜功底包》（景别配比、单镜主动作、时长纪律）→ **渲染这一步换工艺**（见 §2，本次专项）：出的是逐镜镜头卡+首帧指引+负面词，不再是 400 字长文段 → 你逐镜贴模型出 2-5 秒小片，拼成集。成功率上线，因为每一张卡都是视频模型吃得动的紧凑指令。

**漫剧线**：渲染工艺已经是对的（一格一卡+锚段+负面轨+图生视频，`drama.py` SHOT_PROMPT）。skill 补的是**画风→工艺的映射**：你选某画风时，包带出该画风的运镜规范、打光口径、微动幅度基线，并把「分镜功底包」接进格 planning。也就是说漫剧线的 skill 是锦上添花，动漫线的 skill 是雪中送炭。

**灵感线**：点子卡按钩子类型学出卡（悬念/反差/身份/倒计时…），每张卡附「为什么抓人」的归因字段——你带话重出时知道该调什么，不再笼统说「不对味」。

## 2. 动漫线专项：提示词为什么长而出片差（病根确诊）

### 2.1 现状证据链

动漫线渲染提示词的模板 `prompts/anime.py` ANIME_SEGMENT_PROMPT_TEMPLATE + 引擎 `engines/anime/episodes.py build_film_prompt`（L464-502）：

- 按 15s/30s 分段，**一段塞 3-6 个镜头**，逐镜五要素（动作/表情/运镜/光线/衔接）织成一篇连贯长文；
- **每段字数下限 400 字（15s）/ 800 字（30s），上不封顶、不许压缩**（build_film_prompt L477 注释「只设下限，上不封顶」）；
- **角色定妆全文逐段逐字复述**（模板要求 3「定妆描述逐字嵌入」），画风锚逐字开头；
- 台词、音效、衔接说明全部织进同一段文字里贴给模型。

而模板头部写着（anime.py L12-13）：「精度铁律(用户明确要求，全站生成类口径)：细节定死、禁含糊词、不许留白……**篇幅只设下限、上不封顶，不许压缩**」。

### 2.2 为什么这会导致「长但差」

视频模型（即梦/Seedance/可灵/Veo）不是文本模型，它的提示词遵循能力有限：

1. **一次生成塞 3-6 个编排镜头，模型做不到**——它会把动作糊成一锅、蒙太奇乱跳。实证方法论（awesome-seedance 463 个跨模型复测案例）的合格单元是：**一条提示词 = 一个镜头 = 一个主动作，2-5 秒**。
2. **字数超过 attention 预算，模型开始「抽样执行」**——长文里它只抓住几个片段随缘画，剩下的细节全部丢失。写得越满，丢得越多，出来越跟你写的对不上。这就是「提示词很长但内容很差」的直接机制。
3. **定妆全文逐段复述挤占预算还锁不住脸**——纯文字身份锁本来就会漂移；正确做法项目里已有：漫剧线 SHOT_PROMPT 要求 motion「**一个外貌词都不要写**——那一步已经有首帧图把长相钉死了，重复描述长相会让模型把脸重画一遍，人物一致性当场报废」（`drama.py` L418-421）。
4. **多镜长文里的「衔接：」等制作说明是给人看的，模型不执行**，纯耗预算。

### 2.3 讽刺的对照：正确工艺本项目已经在用

| 工艺 | 漫剧线（已用，`drama.py` SHOT_PROMPT） | 动漫线（落后，`anime.py` SEGMENT 模板） |
|---|---|---|
| 提示词单元 | **一格一卡**：prompt_cn 120-200 字六层 + prompt_en 40-60 词 | 一段 3-6 镜长文，400 字起上不封顶 |
| 字数口径 | **紧凑有上限** | 只设下限、不许压缩 |
| 身份锁 | 锚段逐字 + **首帧图生视频**（motion 零外貌词） | 定妆全文逐段复述，纯文字锁 |
| 排除清单 | **独立 negative 轨**（基座+本格规避） | 无负面词槽（系列线有 negative 字段，动漫线没有） |
| 台词 | 后期字幕，不进画面提示词 | 逐字嵌入（音频原生模型，这条动漫线是对的，保留） |

**结论：不需要从外面引进什么高深 skill——把漫剧线验证过的镜头卡工艺提炼成《渲染工艺包》，推广到动漫线，再吸收 awesome-seedance 的两条增量（景别/时长配比等可测参数、排除清单共享库），就是动漫线这次改造的全部内容。** 这才是真正的「融会贯通」：内部已有的正确手艺 + 外部实证的方法论，封装成 skill 资产。

### 2.4 改造方案：动漫线渲染工艺 v2（镜头卡制）

分镜 JSON（shots）**不动**——它已经是好原料。改的是分镜之后的渲染层：

```
现在：shots ──→ 按15s分段 ──→ LLM 写 400字+/段 长文 ──→ 你整段贴模型 → 糊
改后：shots ──→ 定妆照生成(文生图,每角色一张,appearance已≥100字可直接用)
              ──→ LLM 逐镜产三轨(镜头卡) ──→ 你逐镜「首帧+卡」贴模型出2-5s → 按seq拼接
```

每一镜的产物（对照示例）：

```
❰第3镜|6-9秒|首帧:阿黄定妆照(或上镜末帧)❱
  画面卡: 阿黄踮起后爪握锅铲翻锅,耳朵压平又弹起,眼睛瞪圆。中景,机位齐灶台,缓推近。
          暖黄顶光,蒸汽逆光。赛璐璐动画,线条干净。        ← 60-120 字封顶,五要素字段化
  运动卡: 翻锅颠勺两下,蒸汽涌起,眼神从专注到得意。        ← 20-40 字,零外貌词
  台词:   「糊了糊了!」(阿黄,尖着嗓子,语速快)             ← 逐字保留,音频原生模型直接出声
  音效:   锅铲刮底声、油星爆响
  负面:   文字、水印、脸部变形、多指、场景切换、画风漂移     ← 共享负面基座+本镜规避
```

- **身份锁链路**：定妆照（文生图）→ 每镜首帧（定妆照或上一镜末帧）→ 图生视频。文字里身份只留一句锚，不再复述全文；
- **口径修正**：细节照样定死——**但载体换掉**：定死的细节从「塞进长文」改放进「首帧图 + 字段化镜头卡 + 负面词 + 参数（时长/景别/运镜）」。对视频提示词，字数从「下限不封顶」改为**「紧凑封顶」**（画面卡 ≤120 字）——这不是压缩细节，是消灭冗余与重复，让每留一个字都是有效指令；
- 台词/音效/衔接逻辑逐字保留（音频原生与转场是动漫线做对的部分）；合同校验（ask_llm_json）加字段闸：单卡字数上限、禁含糊词、身份锚存在、负面词非空。

> ⚠️ 这条修订动的是你此前定过的口径（「篇幅只设下限、不许压缩」原本覆盖全站生成类）。本方案建议把它**限定在小说正文与剧本**（那里越长越细越好），视频提示词单独走镜头卡口径——**需要你点头，见 §9 拍板 1**。

## 3. 架构：SkillPack 实体与注入纪律

（承 v1 机制篇，挂点按 §1.2 三工序落位）

### 3.1 SkillPack 实体

```jsonc
{
  "id": "render-shotcard-anime", "name": "动漫镜头卡渲染工艺包",
  "scope": ["anime"],              // 适用线与工序: idea / shots / draft / render / polish
  "version": 1,
  "entries": [
    { "node": "render", "kind": "format",     // 渲染工艺:改产物格式与口径
      "directive": "一镜一卡;画面卡≤120字五要素;运动卡≤40字零外貌词" },
    { "node": "shots", "kind": "param",       // 可测参数:进契约校验,不只进散文
      "params": { "shot_duration_max_s": 5, "actions_per_shot": 1,
                  "shot_type_ratio": {"近":4,"中":4,"远":2} } },
    { "node": "render", "kind": "ban_list",   // 排除清单:独立negative槽
      "ban_list": ["文字","水印","脸部变形","场景切换"] },
    { "node": "draft", "kind": "directive",   // 创作工艺:进生成prompt
      "directive": "对白不直说情绪,每场至多一次说破" }
  ],
  "exemptions": [],                // 负向门禁按包豁免(小说线用)
  "eval_ref": "fixture:anime_std"  // 归因回路:改包必跑 baseline 对照
}
```

存储：DB 表，`is_builtin` 只影响 seed 不锁编辑；版本回退抄 `projects.style_profile` 的 {version, history} 模式。

### 3.2 注入三律（防「白水回潮」）

1. **不新增模板占位符**：创作工艺走既有注入缝——小说线 style_block 追加链（`pipeline/chapter.py` L199-231）加 `render_skill_block`；灵感线走 `assemble_tendency` 的 `_custom` 缝；渲染工艺直接作用在渲染模板的选择与填参上（动漫线=模板换装，漫剧/系列线=条目并入）。
2. **注入预算**：单次生成 skill 注入 ≤1500 字、单节点 ≤2 包，超出强制排优先级——31 块全量灌的教训固化成硬闸。
3. **按节点分发**：包条目声明 node，组装时过滤；对白包永远不进分镜，分镜包永远不进正文。

### 3.3 验证与归因（治「改了只能靠体感」）

- 每个官方包绑 evals 夹具；改包=动基线指纹（`evals/prompt_registry.py`），必跑对照出报告（AI 味/blocker/其他维度不许劣化）；
- **动漫线改造的验收是实拍对比**：同一集分镜，旧长文渲染 vs 镜头卡渲染，各挑 2-3 镜真跑视频模型贴图对比——你的眼睛就是裁判，这一步在阶段 1 就做；
- 线上四桶差评按生成时启用包打标，「哪章/哪集被哪个包拖累」可查。

## 5. 落地路径

**阶段 1（动漫线止血 + 包骨架，估 3-4 天）**
1. 动漫线渲染层换镜头卡工艺（模板换装 + 定妆照/首帧指引 + negative 槽 + 契约闸）——这一步独立成立，就算包机制不做也该做，因为它直接治你的痛点；
2. `skill_packs` 实体 + 上述两个试点包 seed + 前端「创作 Skill 包」管理卡（开关/编辑/预览/回退，抄画像卡形态）；
3. 同一集 A/B 实拍对比（旧渲染 vs 镜头卡），你看图拍板。

**阶段 2（门禁 + 包族，估 3-4 天）**：正向门禁两信号（句长节律/用词偏离，确定性可回归）+ 负向门禁按包豁免；其余官方包上线；差评按包归因。

**阶段 3（生态，后置另立项）**：SKILL.md 导入（只读语义子集，绝不执行脚本）；包导入导出分享；范文反推生成用户包（docs/13 杀手锏，等形态稳再做）。

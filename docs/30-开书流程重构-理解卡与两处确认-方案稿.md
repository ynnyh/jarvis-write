# 30 · 开书流程重构:从「确认链」到「理解卡 + 两处确认」(方案稿)

> 状态:草案,待作者讨论拍板
> 日期:2026-10-17
> 依据:docs/29(传国玉玺案例取证)、docs/22(上一轮方案,未落地部分)、两份外部调研(见 docs/31)
> 一句话:全链只留两处确认(理解卡 + 试读);产物层全部「AI 默认、透明可看、随时可改、不拦路」;先小后大;层间保真。

---

## 0. 为什么改(病根,详见 docs/29)

1. **每层重新翻译**:核心种子是对的,角色层一翻译主角就换人了;每层重出都是独立重写,越改越远。
2. **静默字段覆盖**:13 个 token 的题材推断把「真实历史」改成「架空历史」,无确认、下游全吃。
3. **互相卡控**:方案拍板、概念拍板、配置过目、架构逐层、骨架逐段,5+ 道签字段;内容不对时每一道都是纯消耗。
4. **等待结构倒置**:最贵的 7.4 分钟铺章发生在读到任何正文之前;单章正文只要 54 秒。
5. **无留痕**:用户的话全部瞬态,删书即证据消失。

---

## 1. 目标体验(一条主线)

```
小点子 / 参考
  → AI 聊出「理解卡」(它复述、你纠正;每条标「我确定的 / 我拿不准的」)
  → 确认①(读文字,唯一前置确认)
  → 先出样稿 + 前三章(分钟级)
  → 确认②(读正文):满意展开 / 不满意按三档归因
  → 后台铺开(第一卷先铺,后续卷续铺,进度可见)
  → 日常零拍板:下一章直写;质量门禁自动重写≤2轮,仍不过才弹一张说人话的卡
```

两个确认都落在**能读的东西**上(一段文字、一章正文);中间表示(概念七字段/架构四层/骨架段)不再需要用户签字。

---

## 2. 信息架构:理解卡(唯一意图载体)

**字段(草案)**:

| 组 | 字段 | 说明 |
|---|---|---|
| 世界坐标 | 真实/架空、年代、地域 | **坐标级字段,任何下游层不得改写**(玉玺案正是这里被 13 token 覆盖) |
| 视角与主角 | 谁的眼睛、人称、底色 | 「器物第一人称」这类关键设定在此锁定 |
| 味道 | 基调、情绪回报、叙事距离、节奏 | 复用现有 DNA / 味道胶囊 |
| 必须保留 / 不要 | must / avoid | 复用现有 avoid 机制 |
| 参考 | 作品、片段、观感 | 复用「参考方向」卡的分析能力 |
| 形式与体量 | 短故事/连载、档位 | 复用 mode + SCALE_PRESETS;方案卡推荐档默认生效 |
| 题材 | 从坐标派生 | **降级为显示属性**,不再是独立输入字段 |

**生成方式**:AI 从点子 + 参考推导出草案,回读「我听到的是……」,逐条标「确定 / 拿不准」;用户只纠正不对的句子;两三轮收敛。拿不准项可用候选点选(现有三问的候选机制降级为这里的工具,不再是独立关卡)。

**生效**:确认①之后,全链所有生成(样稿/概念/架构/骨架/大纲/正文)从理解卡派生;每个产物可以回答「我是从理解卡哪一条长出来的」。改动全链级联:坐标级改动=下游全部作废;味道级改动=增量修正。

**存储**:把现有 dna / global_tendency / creative_goal 显式化为一张卡,统一写入口;旧字段作为兼容投影保留,不做破坏性迁移。

## 3. 确认点设计

| 位置 | 确认 | 读什么 | 不满意怎么办 |
|---|---|---|---|
| 理解卡 | ① 唯一前置确认 | 文字 | 继续复述/纠正循环,改完再确认 |
| 试读 | ② 内容确认 | 正文 | 归因三档:方向不对→回理解卡;开局不对→重出样稿;局部不对→带话重写该段 |

- **退场(拦路语义)**:概念拍板、配置屏、架构闸门、骨架墙的「必须签」。它们的能力(看、改、带话重出)收进「本书档案」面板,透明可看、随时可改、不拦路。
- **方案墙处置(决策点 1)**:推荐并入确认①同一屏:理解卡回读下方给「三个方向摘要卡」(A/B/C,标 AI 推荐),用户可只确认、可点选、可一句话改。**一屏一次确认**,不另设关卡。
- **保留**:质量门禁照旧自动跑(事实矛盾/截断自动重写≤2轮),仍不过才升级为人工卡(GateResolve 已有)。
- **禁止确认区**(借鉴 chinese-novelist-skill):样稿确认后的铺开过程不打扰用户;想看进度看书档,不看就不看。

---

## 4. 生成链:先小后大

- **样稿链(分钟级)**:理解卡 → 概念(快,参考 3.6 秒)→ 核心种子 → 前三章蓝图 → 正文(参考 54 秒/章)。这是确认②之前唯一跑的东西。
- **后台链**:试读确认后开跑,全书架构四层连跑(带理解卡 + 已确认样稿为硬约束)→ 骨架 → 第一卷铺章 → 后续卷续铺(现有 >150 章分卷机制下放为默认)。
- **铁律**:铺章永远发生在试读之后;重机器(全书架构/铺章)永远在后台,进度可见、可随时喊停。
- 短故事 = 样稿链的自然形态:确认②直接读全文样段,没有后台链。

---

## 5. 层间保真(治「重新翻译」)

1. **硬约束注入**:每层生成把「上游已确认内容」作为最高约束注入;输出附「忠实度自查」,引入新设定必须标注。
2. **重出=增量修正**:带话重出在上一版基础上改,未要求字段逐字保留(定向修订 prompt 已在 2026-09-26 实验验证);输出 diff 展示改了什么。
3. **级联补全**:架构变→骨架作废、骨架变→未铺章大纲作废(现缺这两跳);理解卡变→全链按级别联。
4. **世界坐标不可改写**:真实/架空这类坐标级字段,下游任何层不得变更;违反即打回。
5. **待确认队列**(生态空白位,差异化机会):AI 新增的世界级设定(新角色/新地名/新规则)默认入队、不阻塞写作,在书档「待确认」区随时过目;只有与理解卡冲突时才浮出打断。
6. **字段不静默**:一切「AI 替你定」的动作进书档「AI 已定」区,带来源;推断只填空白,永不覆盖已确认值。

---

## 6. 留痕(三件套 + 顺手修,详见 docs/29 §4)

- 输入快照(每次生成记录所吃的用户输入)、旅程时间线(admin 按书/按用户)、删书软删。
- 顺手修:隐形策划对谈(ghost)删除、铺章纳入记账、job 归属字段补全。

## 7. 外部调研支撑(2026-10-17,详见 docs/31)

**技能生态(实测口径,curl + GitHub API + git clone)**:

- **story-skills 的 premise-workshop**:spark 分类 → 8-12 个 what-if → 每个写成 logline 并跑 stress test,**报 pass/weak/fail + 一句话原因 + 每个弱项一条修订**;原则「作者拥有创意:只提供选项和测试,从不替用户决定」→ 直接升级我们的方向卡/方案卡的呈现方式。
- **chinese-novelist-skill**:三层问答(必答 3 问+可跳过层+自由描述)、「确认区 vs 禁止确认区」、文风基准文件 + 第 1 章后自动回填校准段落。
- **MyNovel**:事实锁 + 哈希锚点、改稿后旧审查失效、每 50 章规划窗口防抢跑、伏笔=待偿债务。
- **oh-story**:状态卡固定 7 栏、硬上限 12KiB、本章技法至多读一份。
- **novel-writer**:每步验证脚本硬阻断 + checkbox 验收清单 + 状态锁。
- **doc-coauthoring(官方)**:Reader Testing,用无上下文的干净模型试读,抓盲点 → 可用于试读环节的自动预检。
- **obra/superpowers brainstorming**:开放式问题优先、选项只在用户卡住时给、每问附「为什么问这个」。

**开源项目前置流程(模型记忆口径,待核验)**:STORM(大纲从素材反推、多视角提问)、Re3(候选比选 + 定向重写)、DOC(先草稿后大纲 + 两级细纲 + 校准回路)、Sudowrite/Novelcrafter(mention 注入 + token 计量)、AI_NovelGenerator(角色状态回写)。

**行业公理(两边共识)**:先问后写;每步产出可验收的中间物;设定是活的(初始最小+随写生长);按相关性注入而非全量;多候选让用户选。**两个公认空白位**:「回写内容走待确认队列再入库」「多候选+比选+定向打回的产品化」——都是我们可以占住的差异点。

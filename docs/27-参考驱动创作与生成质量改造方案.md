# 27 · 参考驱动创作与生成质量改造方案

> 日期：2026-10-01
> 状态：可评审方案；尚未实施，尚未做本轮真实生成对比。
> 范围：小说、漫剧故事和动画短剧的内容质量；本轮只写方案。
> 关联：19 核心梗、20 订单制、21 Skill 包、22 开书流程、23 漫剧源书、17 质量观测。

## 1. 要解决的实际问题

用户选择男频/女频和类型后，候选往往符合分类，却没有想要的钩子、情绪回报与持续吸引力。连载和短篇容易出现动作拆句、重复解释、人物声音相同，规则检查通过也未必耐读。

新的要求是：用户可以给任意参考作品、片段或观感，系统能够识别用户喜欢的具体特征，将它转换成新作品的创作要求，并通过样稿证明理解正确。《屌丝男士》只是一个验收案例，不是需要永久写死的唯一模板。

交付能力应定义为：能处理新参考、能表达依据与未知、能选择合适结构、能生成并校准原创样稿、能追踪后续是否跑偏。不能承诺所有参考一次命中，也不能承诺商业爆款。

## 2. 当前已有能力与真正的增量

以下来自当前源码核查。文档中的历史实施记录只作补充，不代替当前运行验证。

| 环节 | 当前基础 | 本案增量 |
|---|---|---|
| 开书 | 三问、整书方案、定向修订、拍板；旧提案入口也保留 | 在实际开书主链增加参考理解和候选筛选，不再造一套向导 |
| 口味 | StoryDNA、偏好档案、味道胶囊、自定义骨架 | 基于材料的参考分析、用户选择借鉴维度、多参考冲突处理 |
| 文风 | 六维画像、正样本、文风备忘、配对反例 | 统一有效指令，清理互相拉扯的规则，验证编辑前后收益 |
| 小说生产 | 架构、蓝图、草稿、定稿、去味、事实账本 | 从“形式干净”增加到“信息有取舍、人物行动讲得通” |
| 漫剧改编 | 场次、爽点地图、分镜、版本与校验 | 按内容目标采用不同节拍，打脸循环不再覆盖所有作品 |
| 动画短剧 | 固定卡司、三梗纲、独立单集、分镜与提示词 | 完整短剧本、对白喜剧等机制、演员与角色关系的可选配置 |
| 质量观测 | 用量、回炉、确定性指标、章节反馈 | 候选采纳、参考命中、样稿偏好、跨阶段质量损失记录 |

当前重点证据：

- `backend/app/api/projects/plans.py`：当前整书方案生成后经 `_sanitize_plans` 清洗；它核对字段、数量与长度，不承担吸引力和故事机制重复的验收。`avoid` 与反馈已有，不能把它们重复列成新增功能。
- `backend/app/prompts/story_patterns.py`：已有 AI 反推骨架，但默认描述是短剧/网文，要求按章设置频率和必备桥段。需要扩展适用形式与依据，不能强迫段子、短篇都变成长线循环。
- `backend/app/prompts/chapter.py` 与 `polish.py`：存在情绪外化、允许直陈之间的拉扯，也存在与原稿篇幅相当的限制。它们是候选归因点，尚不能仅凭静态代码认定为全部正文问题的根因。
- `backend/app/prompts/drama.py`：剧本硬要求小爽点、大打脸与结尾卡点，限制了情景喜剧等结构。
- `backend/app/prompts/anime.py`：喜剧默认视觉优先，卡司固定、单镜 2–5 秒；已有流程可复用，但其规格不能默认适合所有参考。
- `backend/app/evals/thresholds.py`：确定性底线不等于阅读偏好；当前小说基线也不能作为喜剧表现的证据。
- `docs/23` 实施记录明确将真 LLM 双模式对照留待实测；说明“工程已完成”和“内容效果已验证”需要分开报告。

## 3. 用户体验：描述想要什么，尽快看到作品

主路径：

```text
描述想法/给参考
    → 系统展示简短的理解与原创方向
    → 用户选择或一句话修改，确认创作方向
    → 系统试写，用户直接读样稿
    → 校准后展开作品，日常生成不逐层拍板
```

理解摘要合并进现有方案卡，样稿校准复用现有试读位置。常规路径保留两处主要决策：创作方向与样稿。材料不足或存在无法兼容的要求时，只补问会影响结果的那一个问题。

没有参考也能继续：依据用户描述和已验证的通用机制生成。已有明确设定或正文的用户可以直接续写，不强制重新开书。短篇支持直接出全文；复杂或昂贵任务优先试写。

参考原文、分析证据、细节配置和评分放在可展开区域，默认面向用户展示故事与样稿。

## 4. 核心新增：从参考到可执行的创作目标

### 4.1 输入和证据

接受作品名、用户的观感描述、文本片段、字幕/剧本、可读取的链接；多份参考可组合。每份记录来源、读取范围、定位信息和版本。

只有作品名时，模型只能给“待确认的理解”；不能把熟悉作品名等同于已经读过内容。用户描述可直接成为要求；对原作的判断必须区分材料观察与推断。链接无法读取时说明缺失范围，继续使用已有描述，不假装完成分析。

首版完成作品名、描述、文本/字幕和文本链接的处理。音视频原生分析单独建设转录、画面采样和时间定位能力；未建设前不得承诺已理解表演、剪辑或声音节奏。字幕只能支持对白与文本结构的判断。

### 4.2 分析什么

分析不止“轻松、快节奏、反转多”，而要输出可用于生成与检查的内容：

| 维度 | 应回答的问题 |
|---|---|
| 阅读/观看体验 | 用户想笑、想解气、想追谜、想看关系靠近，还是想读生活质感？ |
| 作品形式 | 连续剧情、独立单集、多段子合集，还是一次讲完？ |
| 推动机制 | 人物如何持续制造事情？优势、弱点与代价是什么？ |
| 信息安排 | 观众比人物多知道还是少知道？误导和揭示如何成立？ |
| 节拍与回报 | 铺垫、升级、兑现、停顿或余味如何组织？ |
| 人物与语言 | 说话的意图、遮掩、关系与叙述距离是什么？ |
| 表现要求 | 文本叙述、对白、画面、声音分别承担什么？ |
| 取舍 | 借鉴什么，不借鉴什么，哪些判断仍不确定？ |

每项关键观察附材料定位或“来自用户描述”的标注。少量片段只能说明所见局部，不能推断整季结构。

### 4.3 用户选择借鉴的维度

例如：A 作品负责生活讽刺与对白；B 作品负责人物关系；用户自己的要求负责温暖结尾。不能将两个参考整段混在一起让模型自由平均。

冲突时先展示具体取舍：连续悬念与独立段子如何兼容；对白喜剧与无对白如何转化。默认给出一个建议，用户可修改。人物/事件/台词另行原创，参考用于提取可迁移的机制与高层特征。

### 4.4 写入同一份有效创作目标

复用现有 DNA、文风画像、方案和 Skill 包；新建的参考分析记录负责来源与证据，不成为第二份故事事实库。

创作目标增加可执行字段：作品形式、期待体验、推进机制、节拍方式、人物声音、详略原则、禁止偏差、适用阶段与来源。现有 DNA/画像是这些维度的兼容投影；生成前计算一份有版本号的有效目标，不让多处存储各自拥有同一字段的修改权。

用户修改旧投影字段时，经统一写入口更新对应目标并产生新版本；旧作品首次使用增强流程才做映射，映射失败保留旧路径并标出未覆盖项。计划/意图仍与已发生事实分开。

指令组合顺序：既定事实和硬规格先校验可行性；用户显式要求优先于参考推断和类型默认；本次修改在指定范围覆盖旧偏好。超预算时先保留事实、有效目标和必要上下文，压缩解释与示例，并记录实际进入生成的材料；不能静默丢掉关键偏好。

## 5. 分开“做成什么”与“让人有什么感觉”

漫剧是表现形式，喜剧/悬疑/逆袭是体验目标，男频/女频是受众信号，二维/三维是真正的视觉配置。这几个维度不能互相代替。

| 创作结构 | 规划与验收重点 |
|---|---|
| 逆袭爽剧 | 委屈与回报对应、主角主动行动、对手有效反击、阶段兑现 |
| 情景段子 | 可识别处境、人物小心思、观众预期、合理误导、包袱与及时结束 |
| 连续情景喜剧 | 人物缺点持续制造麻烦、关系变化、单集闭环与跨集关系 |
| 悬疑故事 | 线索公平、知情范围、误导依据、揭示后的因果一致 |
| 连载小说 | 长期目标、阶段推进、代价、人物变化与持续关系 |
| 短篇小说 | 核心处境、关键选择、集中表达、完整结尾回响 |

这是首批验证结构，采用通用字段加类型专属检查的组合，不按每一个参考作品写一个专用模板。混合类型确定主导结构与辅助效果；新参考可生成临时结构规则，经样稿验证后再决定是否沉淀为复用机制。

复用现有小说、drama、anime 引擎，各自消费相同的创作目标。共享内容目标与检查模块独立放在创作层；不让现有 `media/` 叶子模块反向依赖故事引擎，也不让三条制作线彼此 import 私有逻辑。

## 6. 抽卡改造：控制差异、检查机制、保留喜欢的部分

复用当前方案卡和反馈修订。内部先产生简短候选，完成以下筛选后，只把少量有效方向展示给用户：

1. 硬要求过滤：违背明确禁忌或锁定事实的候选拒绝。
2. 结构去重：比较处境、人物目标、冲突、破局与结果；字面相似度只作辅助。
3. 机制检查：爽剧检查期待怎样兑现；喜剧检查铺垫怎样支持包袱；悬疑检查线索怎样支持真相。
4. 按用户目标比较：以具体事件为证据说明候选的长处与缺陷，不让模型只给泛化高分。

展示仍是现有方案卡，但重点内容更具体：开局事件、第一处回报/包袱、下一步如何变化、为什么值得展开。内部解释不必全给用户看。

锁定按语义字段执行。修改对手时，不擅自改主角和已认可的核心机制；检查被锁字段以及依赖变化。候选都不合格时，最多补生成一次；仍失败就展示实际问题与修改建议，不无限重抽，也不为凑三张放进弱卡。

第一轮不建立庞大题材数据库。将真实分析与通过试读的原创样稿逐步沉淀成机制库，并保留失败对照；入库必须记录适用形式与证据，不能把未经阅读验证的自动摘要当作质量标准。

## 7. 小说改造：处理信息取舍与因果，允许合理缩短

先保留草稿、定稿、字数处理、去味各版本，逐段检查质量损失发生在哪一层。随后调整真正有问题的阶段。

编辑顺序：事实/因果问题 → 场景组织 → 信息取舍 → 句子修订。复用现有一致性和审校机制，不增加多个重复全文润色步骤。能局部处理的就局部处理，通常只做一轮编辑，必要时一次修复。

专门处理以下现象：

- 一个普通动作拆成多句，但没有增加信息。
- 行为/对白已经表达意思，又解释一次心理或结论。
- 去掉套话以后，用更多身体动作替代一个普通情绪判断。
- 每个场景均匀展开，重要决定与普通过门占同样篇幅。
- 人物对白只负责交代背景，没有说话目的和关系差异。

编辑允许删除无效文字，篇幅区间服从实际事件容量。删掉冗余导致低于旧字数，不自动扩写回去；先判断是否缺必要场景。直接陈述情绪、普通过渡与安静片段均可保留，不把“人味”变成新的禁词竞赛。

事实账本、知情范围与章后更新复用当前机制。增强链的试写与弃用版本不得污染正式事实；定稿修改后重算受影响记录，并标记后续相关规划或稿件需要核对。

## 8. 《屌丝男士》类需求的落地案例

仅以本次用户明确描述作初始假设：日常处境、对白驱动、人物小心思、一本正经的荒唐、短段子反转收尾。具体原作特征须在获得材料后分析，不能仅凭作品名宣称已验证。

复用动画短剧主链，增加可选的情景段子结构：

- 人物档案增加欲望、弱点、维护的自我形象、惯用辩解，以及角色间的冲突关系。
- 区分固定角色系列与演员反复扮演不同身份的合集；演员视觉资产与单段角色身份分开记录。
- 支持经用户允许的单集客串，维持现有固定卡司作品的约束。
- 先写完整短剧本，再拆分镜；用对白与动作判断包袱，不能从简短梗纲直接判定好笑。
- 单段或一集包含多段可配置；首版先验证独立单段，多段合集放在第二阶段。
- 结尾可完整收住，不强制下一集悬念、大打脸或主角获胜。
- 分镜按揭示与表演节拍安排，允许必要停顿；外部视频段长限制在镜头规划后处理，不能为了规格提前揭底或切断包袱。

机制检查回答“观众先以为是什么、实际是什么、前面依据在哪里、是否过早泄露”。结构成立只说明包袱讲得通；是否好笑由真实读者试读和后续表演样片验证。

此路线当前只产内容与提示词。剧本验收不能宣称已经验证视频模型的表演与成片效果，也不擅自扩展本站自动出片范围。

## 9. 验收：证明可以处理新参考，证明用户更满意

### 9.1 首轮诊断基线

选六组真实目标：男频逆袭、女频关系反转、日常段子喜剧、悬疑独立短剧、生活质感连载、完整短篇。记录当前主入口、实际配置、模型、提示词版本、材料范围、各阶段文本、耗时和费用。

同任务至少生成两次，避免只展示幸运样本。第一轮用来定位问题，不称为全面统计证明。

### 9.2 对照与未见参考

固定输入与模型配置，对比旧流程与新流程；另选开发时未用过的参考片段，覆盖至少三种结构与两种语言表现，验证泛化。混合参考、未知作品名、无参考、缺失链接、冲突要求也必须覆盖。

人工匿名成对判断允许“A 更好 / B 更好 / 都可用 / 都不可用”，记录原因。创作者判断优先，再引入目标受众做扩大验证。同模型自评与自动指标只辅助诊断。

指标分开统计：方向一次采纳率、到可用样稿的重做次数、参考特征命中、继续阅读意愿、无效句比例、因果硬伤、喜剧段子可用率、编辑前后偏好、分镜后包袱保留情况、总成本与时延。

### 9.3 初始放行条件

- 明确锁定字段和硬约束的覆盖用例全部通过；来源未读不得标已读，失败不得静默降级。
- 每种目标分别报告，不能用爽剧平均提升掩盖喜剧或小说退化。
- 初轮成对对比中新流程优选不少于 60%，且用户认为达到可用；小样本结果只用于决定是否扩大试验。
- 专项喜剧六命题各两候选，至少四个命题有一版用户愿意制作；这只是首版探索门槛，不是稳定爆笑证明。
- 工程底线不退化；编辑后事实丢失不允许，新增不合理因果必须修复。
- 首轮实测后设定可接受的重做率、成本和等待上限；最终效果未达到时缩小支持范围或回退增强路径。

## 10. 实施分期与产物

| 阶段 | 工作内容 | 必须交付的证据 |
|---|---|---|
| P0：先定位 | 当前六类任务基线；提示词冲突与注入盘点；分阶段质量对比 | 实际样稿、配置清单、损失位置和优先修复项 |
| P1：参考理解 | 文本参考分析、选择借鉴维度、统一有效目标、接入实际方案主链和 anime 梗纲 | 未见参考测试、理解摘要、来源记录、两条入口生成快照 |
| P2：内容改善 | 类型节拍分发、候选筛选、完整喜剧剧本、小说冗余编辑、一次必要修复 | 六类旧/新匿名对照，用户采纳与成本结果 |
| P3：持续稳定 | 多参考、合集/客串、跨阶段一致性与反馈归因；通过试读的机制沉淀 | 连载续写、喜剧多集、修改联动和回退实测 |
| P4：按需扩展 | 原生音视频参考与表演样片验证 | 可定位的转录/画面证据、单独的成片效果验收 |

各期使用功能开关与版本快照，先在新建或主动选择增强流程的作品启用。旧作品默认维持当前解释与规则；新结构启用时重新计算适用包，避免全局爽文包压过喜剧目标。每期先通过样稿门槛，再展开后一阶段，不把“包接上了”算作内容交付。

实现验证覆盖目标编译、来源状态、锁定修订、类型分发、版本失效与普通作品回归；按项目规定完成对应工程检查。真实生成测试单独记录用量；运行前核实配置与试验预算，使用隔离数据，不覆盖现有作品。

## 11. 首版边界与工程落点

首版包括：文本参考到有效目标、实际方案主链筛选、小说编辑规则收口、动画短剧完整剧本与情景喜剧适配、真实对照验收。首先修复影响质量的环节，不重复建设订单、画像、账本和 Skill 管理。

建议落点：

- `schemas/dna.py`、`engines/style_profile.py` 及偏好写入口：兼容现有维度；共同目标的版本与投影规则需先定。
- 新的参考分析与目标编译模块：解析依据、字段归属、冲突和按阶段渲染；轻量数据契约先行，不上复杂自治调度。
- `api/projects/plans.py`、`prompts/inspire.py`：实际方案卡生成、筛选与锁定修订；不只修旧提案 API。
- `prompts/chapter.py`、`polish.py`、`engines/pipeline/`：以 P0 证据决定删哪些重复编辑或限制。
- `prompts/drama.py` 与对应引擎：按目标选择节拍，保留现有爽剧规则作为适用配置。
- `prompts/anime.py`、`engines/anime/`、`models/anime.py`：接入参考目标、完整短剧本、角色/演员可选关系及修改失效。
- 现有 onboarding、动画短剧工作区和反馈面：展示理解、有效候选与样稿，复用当前 UI 公约。
- `evals/` 与既有质量观测：扩展专项样稿与反馈，不以正则分数替代观众判断。

明确后置：自动搜集海量爆款库、模型微调、大规模多代理创作、全制作线重构、自动发布。它们尚无证据能优先解决本次瓶颈。

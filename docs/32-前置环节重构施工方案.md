## 1. 新流程(小说线,含漫剧源书)

```
屏0 开哪种书(mode,保留)
  → 屏1 想法(idea,保留:灵感/流派/皮肤/参考方向卡)
  → 屏2 理解(intent,新):
       · 理解卡:AI 回读「我听到的」——世界坐标/视角与主角/味道/必须保留/不要/题材(派生)
         · 每条标「确定 / 拿不准」;拿不准项带候选(吸收三问机制为工具,不再是关卡)
         · 可整卡重出(带一句反馈)、逐条改
       · 方向卡 ×3(复用 book-plans):紧凑卡(书名/内核/主角/世界/首章走向/标签)
         · 选一套 / 改改再选(复用 revise-plan)/ 再来三套
       · 确认①「✓ 就按这个来,先写三章给我看」
         → 落库:brief(渲染自选中方案)+ brief_confirmed + intent_card + 题材 + 篇幅
         → 启动 sample-chain(后台)
  → 屏3 样稿(sample,新):
       · sample-chain 进度(概念→梗卡→核心种子→前三章蓝图→前三章正文,分钟级)
       · 前三章正文可读(复用 Reader 组件,含移动端目录抽屉)
       · 确认②:
           「读着对味,继续写」→ 启动 full-chain(后台),进工作台
           「方向不对,回去改」→ 回屏2(可改理解卡/换方向;重确认后重出样稿)
           「开场不对,重出样稿」→ sample-chain 带 directive 重跑(蓝图+正文,跳过已有概念/种子)
           「第 N 章不对」→ 单章带话重写(复用 chapter revision 通道)
```

- 旧屏退场:PlanFlow / ConceptForge / ArchGate / SkeletonWall / setup 三页签从主流程删除;
  其「可看可改」能力保留在工作台开书区(ArchPanel / OutlinePanel / BoardPanel 已挂载,无需新建)。
- 存量书兼容:parseStep 映射(concept/setup/launch → sample;generating → sample;brief → intent);
  未拍板的落 intent。ProjectsPage「继续创建」与 ProjectPage 跳转照旧走 parseStep,不断链。

## 2. 后端改动清单

### 2.1 新端点(api/projects/intent.py,新文件)
- `POST /{pid}/intent-readback`:FAST 档,输入 topic/mode/genre/references/feedback → 回读 JSON
  (字段 + uncertain 候选);不落库(草稿),gen_inputs 记快照。
- `POST /{pid}/intent-confirm`:body {index, mode, card, scale_override?} →
  存 intent_card + genre(显式)+ 渲染 brief(_render_order 复用)+ brief_confirmed=True + 篇幅应用
  → spawn sample-chain → 返回 {project, sample_job_id}。旧 plan-confirm 保留不动(兼容)。

### 2.2 生成链(api/projects/chain.py,新文件)
- `POST /{pid}/sample-chain`(body 可选 directive)→ 幂等任务 sample-chain-{pid}:
  1. 概念深化(_develop_impl 复用;concept 已存在则跳过)
  2. 梗卡(_SUGGEST_PROMPT 复用;已有则跳过)
  3. 核心种子(generate_architecture_layer 复用 + save/confirm;已有则跳过)
  4. 前三章蓝图(generate_blueprint end_chapter=min(3, target_chapters);outline 已有且无 directive 则跳过)
  5. 前三章正文(逐章 generate_chapter;已有 final_content 且无 directive 则跳过)
- `POST /{pid}/full-chain` → 幂等任务 full-chain-{pid}:
  1. 其余三层架构(带「已写前三章为既成事实」约束;自动拍板)
  2. 骨架(卷纲/分段,复用 skeleton 引擎;全拍板态)
  3. 全书蓝图(复用 blueprint-async 的滚动规划 runner,提取为共享函数)
- 防重入:list_running 去重;每步独立短事务(session 开合随步骤,不跨 LLM 调用持有)。

### 2.3 保真与级联
- `render_intent_block(project)`:理解卡渲染为硬约束块,注入架构四层/骨架/蓝图
  (走既有 style_directives/hard_note 通道,模板与评测指纹零变更)。
- 世界坐标守卫:架构层 prompt 明示「世界坐标不得改写」;save 层时比对坐标关键词(轻量提示,不做硬拦)。
- 增量重出:architecture layer 的 directive 通道升级——prompt 带当前层文本 + 「未要求修改的部分逐字保留」(复用 REVISE_PLAN 的模式)。
- 级联补全:架构层保存 → 新增 `project.skeleton_stale=True`(已有 outline_stale 逻辑保留);骨架重出 → outline_stale=True;save_blueprint/skeleton 重出各自复位。前端在大纲/骨架面板显示 StaleBadge + 重出入口。

### 2.4 留痕
- 新表 `gen_inputs(id, project_id, job_id, kind, payload JSON, created_at)`;helper `record_gen_inputs`;
  埋点:intent-readback / book-plans / revise-plan / intent-confirm / arch-layer / skeleton / blueprint / chapter(revision)。
- 软删:`projects.deleted_at`;DELETE 改为置位(不再级联物理删);`_get_project_or_404` 过滤;列表过滤;
  admin 列表含 deleted 标记;清理任务:deleted_at 超 30 天 → delete_project_cascade 物理清。
- job 归属:concept 生成 kind 改 `inspire-develop-{pid}`(两处);title-suggestion 请求体加可选 project_id。
- 流式记账:`_generate_chunk` 流式成功路径补 `_record_usage`(估算 token,finish_reason="stream");

### 2.5 数据与迁移(migrate.py 补 ALTER)
- projects:+intent_card(JSON)、+skeleton_stale(BOOL 默认 0)、+deleted_at(DATETIME 可空)。
- gen_inputs 新表走 create_all 自动建。
- schemas/project.py:ProjectOut 增 intent_card / skeleton_stale(不暴露 deleted_at)。

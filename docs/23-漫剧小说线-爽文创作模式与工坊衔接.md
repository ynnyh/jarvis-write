# 漫剧小说线：爽文创作模式 + 漫剧工坊衔接

> 设计日期：2026-09-26 · 代码基线：`main` @ 45f1376
> 触发：红果 AI 漫剧爆款调研（2026-09）——爆款公式「3D 稳定画质 × 网文 IP × 长线连载 × 单集爽点+结尾钩子」，60% 爆款改编自网文爽文；而咱们漫剧工坊吃的源是传统小说线产出的文学长篇，爽点密度结构性不足。
> 前序：docs/21（Skill 内置方案，包机制）、docs/09（新建小说向导）、docs/20（订单制）。

## 0. 一句话结论

**不动现有小说线一行口径，新增「写漫剧剧本」开书入口：底层完全复用小说线（Project/Chapter/流水线），文体口径全部走 SkillPack（《漫剧爽文包》，scope=novel），写完的书天然衔接漫剧工坊转拍摄手册。** 工程量最大的一块不是新功能，而是把 novel 生成链接上 skill 包注入槽（该机制 anime 线已在用，novel 线还没接）。

## 1. 问题定义：文体断层

调研结论（详见会话记录，数据源：雷报/艾媒/DataEye/36氪）：

- 红果前 30 漫剧爆款 60% 改编自网文爽文（多为番茄腰部 IP），76.7% 至少 3 季；
- 爆款单集形态：50 秒上下、前 3 秒冲突前置、结尾卡点戛然而止、集集爽点兑现；
- 行业爆款率仅 0.47%——缺的不是生成能力，是「高密度爽点叙事」的编剧能力。

咱们现状的四条线（小说 / 漫剧工坊 drama / series / anime）里，**drama 工坊已经是「小说→拍摄手册」的完整桥**（风格卡/角色卡/集规划/剧本/分镜/三轨提示词，且集规划天生红果口径：`hook` 3 秒抓人、`cliffhanger` 卡点、首集即全书最强钩子，见 `prompts/drama.py` EPISODE_PLAN_PROMPT）。断的是上游：

| | 传统小说（现状） | 漫剧源文稿（红果爆款的源头） |
|---|---|---|
| 原子单位 | 章（3000 字默认，铺垫慢热合法） | 集（对应 50s 成片，800-1500 字一个完整爽点循环） |
| 章末 | 交接契约（承上启下即可） | 必须钩子（新麻烦/新信息露头，停在具体动作/台词） |
| 心理描写 | 合法且被鼓励（文风备忘沉淀声音） | 一律外化成台词/可视动作（要可拍） |
| 对话占比 | 无要求 | 过半，单句 ≤25 字 |
| 节奏 | 起承转合自由 | 每章必兑现一次爽点，不许拖章 |

把右列灌进 `chapter.py` 的现有口径 = 污染传统写作体验，两边不讨好（作者已拍板：不动现有小说线）。所以做**独立入口 + 复用底层**的新模式。

## 2. 产品形态

### 2.1 入口：开书向导分岔 + 频道选择

开书入口两张卡：**「写小说」**（现有流程，零改动）vs **「写漫剧剧本」**（新模式）。

选「写漫剧剧本」后向导差异（按 docs/09 的向导骨架调整文案与默认值，不改流程结构）：

- **频道选择步**：「给谁看——男频 / 女频」二选一。这是漫剧向导里新增的一步关键拍板：它决定自动挂哪个爽文包（§3.2 双包设计），即整本书的题材皮肤库与情绪侧重。选完之后不再追问频道相关问题，细节全靠 AI 堆。频道是书属性不是入口——**不把开书入口分裂成四张卡**；
- 创作目标文案变化：不问「想写一个怎样的故事」而问「想让人追什么」——按「被低估的主角 × 可视化金手指 × 正义动机」引导出点子（AI 出点子兜底逻辑同现有，点子按所挂包的皮肤清单出，见 §3.2 idea 节点）；
- 默认参数：`open_ended=True`（开放式连载——现有字段，漫剧模式直接默认开，架构只定「长线引擎+首批方向」）、`target_chapters` 默认 60、`target_words_per_chapter` 默认 1500（一章≈一集）；
- 完书后引导：完结页/书页给「去漫剧工坊改编」直达入口（工坊已存在，纯前端引导）。

### 2.2 心智：一本书，两个出口

漫剧小说本身就是可发布的网文（发番茄=IP 是用户自己的），转漫剧是第二出口。产品叙事：**写书 → 漫剧验证 → 数据说话**，藏山从「出片工具」升级为「个人作者的 IP 孵化器」。

### 2.3 数据流闭环

```
开书(漫剧剧本) → AI 点子(爆款四件套配方) → 架构(长线引擎) → 逐章流水线(爽文口径)
                                                                    ↓
出片 ← 三轨提示词/镜头卡 ← 分镜 ← 剧本 ← 集规划(章↔集对齐) ← 漫剧工坊(现有)
```

工坊侧零新建（它本来就挂在 project 上，`_require_approved` 后即可改编），只做两处小增强（§3.4）。

## 3. 实施设计

### 3.1 数据模型（最小改动）

`projects` 表加两列：

```python
# app/db/models/project.py
content_mode: Mapped[str] = mapped_column(String(20), default="novel")   # novel | drama_source
audience: Mapped[str] = mapped_column(String(10), default="")           # "" | male | female（仅 drama_source 书有意义）
```

- alembic 迁移 `0014_project_content_mode.py`：加两列，存量书全部 `novel` / 空串；
- **职责边界（铁律）**：两个字段都只管「意图与默认值」——向导文案/分岔、默认参数、自动挂包、工坊徽标。**字段值本身绝不直接进任何生成提示词**，文体口径一律走 SkillPack。理由：docs/21 风险 8 的原话——不许长成「写死审美 2.0」；`audience` 决定挂男频包还是女频包（选择挂哪个包），但不把自己的值拼进 prompt 文本。

### 3.2 爽文双包：《男频爽文包》+《女频爽文包》（本方案的核心资产）

原设计单包《漫剧爽文包》，拆成**两个互斥的官方内置包**：`pack_key="drama_source_male"` / `"drama_source_female"`，`scope=["novel"]`，随 seed 分发（复用 `engines/skills/packs.py` 的内置包机制），is_builtin=True 但可编辑可关闭（关掉即退化为普通书，无害）。向导选频道时自动挂对应包。

**为什么拆双包而不是单包带参数**：`active_packs` 按 scope+node 过滤，没有「按书的字段选内容」的机制；拆双包后「audience → 挂哪个包」与「content_mode → 自动挂包」是同一个模式，机制零改动。公共骨架（爽点循环/章末钩子/可拍性）两包各带一份——重复是刻意的：改男频包不影响女频包，天然隔离。

节点白名单 `VALID_NODES = {"idea", "outline", "draft", "polish", "shots", "render"}` 全覆盖需求，**无需扩节点**。

**① node=idea（开书点子/灵感出卡）——双包差异最大处**

公共骨架（两包同文）：
> 点子按爆款四件套出：①被低估的主角（身份/年龄/地位至少一层反差）②可视化金手指（图鉴/系统/阶位/清单——把「变强」变成看得见的收集进度）③正义动机（复仇/守护/讨公道——冲突要有理由）④信息差底牌（观众知道、剧中人不知道的牌）。骨架固定，血肉（题材/人物/具体桥段）必须具体且互不雷同。

男频包追加（皮肤清单 + 情绪侧重）：
> 题材皮肤优先从清单选：扮猪吃虎/系统流/玄幻修仙/赶山狩猎/种田经营/末世求生/都市战神/职场打脸/历史权谋/高武御兽。爽点侧重：碾压感（实力/身份反差兑现）、收集感（金手指进度可视化）、权力感（地位跃迁打脸质疑者）。

女频包追加（皮肤清单 + 情绪侧重）：
> 题材皮肤优先从清单选：大女主复仇/重生虐渣/豪门恩怨/马甲大佬/追妻火葬场/年代空间/宅斗宫斗/先婚后爱/穿越种田/萌宝逆袭。爽点侧重：情感浓度（误会/偏见的翻转）、关系反转（被轻视者掌握主动）、自我救赎（不靠拯救者，自己破局）。

用户可越过清单自由描述自己的题材——清单是出点子的默认货架，不是限制。

**② node=outline（章纲/蓝图）——两包同文**
> 本书是漫剧源书，每章≈一集成片。章纲必须按爽点循环编：①开场即冲突/悬念，前三行进事；②压抑或递进（被低估/受挫/加码，不超过半章）；③爽点当章兑现（打脸/升级/揭示/反转，至少一次，禁止拖到下章）；④章末钩子（新麻烦露头/新信息炸出/危机悬置，必须停在具体的动作或台词上，禁套话）。

**③ node=draft（正文草稿/定稿）——两包同文（情绪侧重微调可后调）**
> 漫剧源书正文口径：对话占比过半，单句台词≤25 字；心理活动一律外化成台词或可视动作；场景写到「可拍」（人物位置/动作/物件具体，不写抽象氛围）；禁连续两段纯环境描写；爽点兑现瞬间给足反应（对方的震惊/失态/围观哗然）；章末最后一行必须是钩子的具体落点。

**④ node=polish（审校）——两包同文**
> 漫剧源书审校加查四项：本章爽点兑现了吗（兑现的是什么、在第几段）；章末钩子具体吗（停在动作/台词还是停在套话）；前三行有冲突/悬念吗；有没有连续三段无对话的文戏淤积。

### 3.3 基建：novel 生成链接入 skill 包（工程量主体）

`render_skill_block(db, scope=…, node=…)` 目前只有 anime 线在调（`engines/anime/episodes.py:351`）。novel 线需要在四个工序的 prompt 组装处各开一个注入槽（每处约 5 行：查包、拼块、塞模板占位符）：

| 工序 | 注入位置（实施时定位具体组装函数） | node |
|---|---|---|
| 开书点子 | `prompts/inspire.py` 对应的出点子链路 | idea |
| 架构/章纲 | `engines/outline_discuss.py` / 蓝图生成处 | outline |
| 章节草稿+定稿 | `engines/pipeline/`（chapter.py 模板加 `{skill_block}` 槽） | draft |
| 审校/润色 | `engines/polish.py` / 审校链路 | polish |

注意点：

- **普通书零污染**：`active_packs` 只返回「启用 + scope 命中 + node 命中」的包；普通书不挂爽文包，注入块为空串，模板占位符替换为空——生成结果与现状逐字节一致（验收项，见 §5）；
- **预算闸冲突**：`MAX_PACKS_PER_NODE=2`，爽文双包互斥挂载（一本 drama_source 书只挂男频或女频其中一个），单节点始终只占 1 位，用户自选包仍有 1 位余量；
- **防趋同联动**（对齐 main @ 45f1376 的防趋同改造）：爽文包写死的是「循环骨架」，条目里显式要求血肉具体、点子互不雷同；发散类任务的提温/avoid 注入机制照常叠加，不冲突。

### 3.4 漫剧工坊衔接增强（两处小改）

1. **集规划感知源书**：EPISODE_PLAN_PROMPT 已有 `{mode_desc}` 改编模式参数——加一档「漫剧源书」：每章已自带爽点循环与章末钩子，切集以一章一集为默认、cliffhanger 优先升格本章章末钩子。这样集规划从「从文学章里挖冲突」变成「对齐现成的钩子」，巧妇有米了。
2. **源书徽标**：工坊页对 `content_mode=drama_source` 的书显示「漫剧源书」标记（纯展示，便于用户区分两类书的改编预期）。

顺带核对过不需要改的：分镜「第一格直接给 hook 的画面，不做片头铺垫」drama 线已有；三轨提示词的一格一卡+首帧图生视频工艺已对齐行业主流。

### 3.5 anime 线顺手小改（独立于本方案，可单独做）

调研启发落点：`prompts/anime.py` ANIME_SHOTS_PROMPT 精度铁律加第五条——第 1 镜必须冲突/悬念/结果前置开场，禁用环境空镜与缓慢建立（完播导向）。漫剧小说线合入后，anime 线的「季/连载结构」另行立项（本方案不含）。

## 5. 验收标准（实测证据，不合糊）

1. **零污染**：同一本普通书，接入前后各生成一章草稿，除随机性外口径无变化；skill 注入块为空串断言。
2. **文体可辨**：同一个开书点子，「写小说」与「写漫剧剧本」各出第一章：漫剧模式章末钩子具体落点、对话占比、爽点当章兑现三项肉眼可辨（附对照样本）。
3. **频道可辨**：同一个四件套骨架点子（如「被低估的主角+可视化金手指」），男频/女频各出三组点子：皮肤与情绪侧重肉眼可辨（男频出碾压/收集向，女频出情感/关系反转向，不串味）。
4. **衔接闭环**：漫剧源书跑工坊集规划——一章≈一集对齐、章末钩子→cliffhanger 升格率（抽查 10 章人工核对）。
5. **可退化**：关掉爽文包后，漫剧书继续写即普通书口径，无残留。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 爽文套路=结构性同质化（加重「重出同批」老问题） | 包只锁循环骨架，条目显式要求血肉具体；沿用防趋同提温/avoid 机制；idea 节点三点子互不相同要求保留 |
| 皮肤清单过时（平台题材风向轮动快，如「经营」标签 2.9%→38.4%→17.8%） | 清单是包条目，改清单=改包（版本化+可回退），不打代码不发版；按榜单节奏滚动更新 |
| 频道选择增加向导步骤 | 一步二选一、AI 出点子兜底按所选频道出卡；「写小说」路径完全不受影响 |
| 注入预算争位 | 双包互斥挂载，单节点只占 1 位，用户包仍有余量；包管理页开关可见 |
| 向导分岔增加开书复杂度 | 两张卡一屏选完，不新增步骤数；「写小说」卡片默认高亮不变 |
| 漫剧源书发番茄的合规（AI 生成内容标识） | 平台侧已要求 AI 标识，导出/发布流程提示用户自行标注——不在本方案范围，记入观察项 |

## 7. 实施记录(2026-09-26,P1-P4 一次落地)

全部按 §3 设计落地,三处与原设计的偏差/增补:

1. **不加 `content_mode`,复用 `mode` 列**:调研落地时发现 `projects.mode` 就是 docs/22 屏 0 的开书模式落库位(serial/short),向导分岔机制天然存在——drama 直接作为第三个枚举值接入,不另起字段。新增列只有 `audience` + `mounted_packs`(迁移 `0014_drama_source_books`)。
2. **`render_pack_block` 补了条目级节点过滤(既有缺陷修复)**:原实现只按「包内是否有该 node 条目」筛选包,渲染时却把包内**全部条目**都注入——anime 首批包每包单节点从未暴露;爽文双包每包四节点,不修则 draft 里会捎带 idea 条目。现 `render_pack_block(pack, node)` 只渲染命中节点的条目。
3. **顺手修了场景级定稿的既有 bug**:`pipeline/chapter.py` 场景级路径的 `CHAPTER_FINALIZE_PROMPT.format` 一直缺 `premise_block`/`tension_bus_block` 两个模板占位符(scene_level_enabled 默认关所以未炸),本次补齐并带上 skill_block。

向导分岔的落地形态:屏 0 第三张卡「🎬 漫剧剧本」+ 卡下频道选择(男频/女频),默认 60 章 × 1500 字;简介聊天(brief-chat)已按书的挂载注入 idea 节点——挂包后向导出点子/聊简介即按爽文四件套与所选频道皮肤货架引导,无需为向导单独写分岔提示词。三问/方案卡流对 drama 书沿用连载形态(后端归 serial,漫剧本质是长线连载,方案形态成立)。

测试(全绿):后端 1634 passed(新增 `test_novel_skill_injection.py` 13 项:零污染/挂载语义/双频道可辨/建书行为/迁移默认值);前端 tsc + eslint + vitest 287 项 + vite build 通过;alembic 全新库 upgrade head 验证 0014;schema 漂移门禁通过。真 LLM 的双模式对照样本(普通书 vs 漫剧书首章、男频 vs 女频点子)留待线上实测验收。

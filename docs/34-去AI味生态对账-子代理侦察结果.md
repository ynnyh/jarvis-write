# 34 · 去 AI 味生态对账(子代理侦察结果 + 我们的缺口)

> 状态:调研对账(2026-10-17)
> 来源:子代理侦察报告(实测读码,覆盖 humanizer / avoid-ai-writing / shuorenhua / oh-story /
> chinese-novelist / AI-Novel-Writing-Assistant / lieflat / swaylq / stop-slop 等 10+ 仓库)。
> **声明**:§1 的仓库细节是子代理的实测结论(附了文件与行号),不是本文档作者逐条复验的;
> §2 的「我们」一栏是本文档作者**对着本仓库代码复核过**的。

---

## 1. 生态水位(子代理实测,摘要)

- **检测**:真实水位是「正则词表 + 少数 stylometric 统计量」(burstiness / TTR·MATTR / 函数词
  trigram 熵 / 标点分布 / n-gram 困惑度),几乎没人用分类器。**分水岭不在检测器,而在
  有没有真人语料标定、标定后敢不敢把不可分指标降级**。
- **打分**:单一 AI 味总分被视为不成熟标志——工程最彻底的 `avoid-ai-writing`(零依赖 JS 引擎,
  54 type,阈值来自 376 篇真人语料,门禁门在 `issues.length` 而不在 score)有分但门禁不用分;
  两个最认真的中文仓库(`shuorenhua`、`oh-story`)**明文拒绝单一分数**。
- **改写**:共识收敛到「定点 patch + 编辑预算(触及比例上限)+ 机械保真校验器 + 失败返回原文」,
  整篇重写是成熟项目**刻意避免**的。
- **回路**:写前约束 + 写后门禁 + 最多 1-2 遍 + 失败如实保留;共同哲学是**宁可漏改不可误杀**。
- **评测**:冻结协议/哈希/盲测是标配,**但整个生态没有一家做过真正的人类盲测**,判分全依赖
  LLM judge 且多处记录不可复现。
- 只有营销话术、查无实现:`humanizer` 的 16/16 盲测、`stop-slop` 的 /50 分与 <35 阈值、
  `ai-flavor-remover`(全仓只有一个 README)、`avoid-ai-writing` 的「74 categories」(引擎实际 54)。

|---|---|---|
| 定点改写替代整章重写 | `deai_heal_repeats`(v0.58 新增)已是段落级;但**主路径 `deai_rewrite` 仍是整章**(`draft_text=text`) | **部分缺**,主路径待改 |
| 长度带安全阀 | 有:`_DEAI_LEN_LO/HI = 0.75/1.25`(两道自愈都用) | 已有 |

## 3. 下一轮候选(按性价比,供拍板)

1. **机械保真校验器**(小改动,风险最低):整章去味重写采纳前,先做纯规则校验——数字、
   人名/专名、引语、段落数是否守恒,不守恒直接丢弃。生态共识项,且我们现在只有「篇幅比 +
   分数 + 统计判据」三关,防不住「顺手改掉一个数字」。
2. **主路径改定点 + 编辑预算**(中等):`deai_rewrite` 只重写命中句所在段落,并给触及比例上限
   (如 ≤30% 段落)。收益是成本与风险双降;代价是要重做命中→段落的映射与验收。
3. **阈值标定记录 + 降级不可分指标**(中等):拿 `evals_corpus/` 与线上语料(聚合口径)做一次
   人类侧 vs AI 侧的分布对照,给每个阈值留下出处;分不开的指标(候选:段长 CV、4-gram 新颖率)
   主动降级为「只作提示不作罚分」。这条最符合侦察里「分水岭」那句话。
4. **AI 味门禁改二维**(较大,需设计):把「一个分数过不过线」换成
   `blocking/advisory × mechanical/semantic`——机械项(词表命中、重复)可 blocking,
   语义项(空洞比喻、情绪直喊)只 advisory。避免单一分数一刀切。
5. **黄金集 + 误改率门槛**(评测侧,一次性):冻一批「改前/改后」对,加一条
   「正常文本误改率 < 10%」的发布门槛,以后动去味规则先跑它。

**不建议做**:照搬 `avoid-ai-writing` 的三分类(GPTZero 形状,为「判别是否 AI 生成」设计,
与我们的「改文风」目标不同);引入中文水印/同形字检测(场景不符)。

# 36 · 进化系统 P0 施工方案:复盘提炼 + 三档自治旋钮 + 开书回注

> 状态:方案稿(随本版实施,P0 范围已实现)
> 日期:2026-10-17
> 依据:docs/29(留痕)、docs/30+32(理解卡与前置重构)、docs/35(文风指纹,未开工)
> 一句话:让系统从「每次生成都独立抽卡」变成**会复盘的写作系统**——书写完后,Agent 自己读证据(作者采纳了什么、删改了什么、说过什么),提炼成带出处的记忆条目;下一本书开书时,确认过的记忆注入理解卡回读,随卡传遍全链。

---

## 1. 愿景与形态判断(为什么这么做)

目标形态是「大模型 Agent 的那种进化」。技术事实:**模型权重动不了**(API 路径,按用户微调在成本/数据量/遗忘上都不现实),所以进化全部发生在**上下文与资产层**——这与 Claude Code 记忆、Voyager 技能库、DSPy 提示词自优化是同一形态。它与「一次性总结提炼」的差别在三点,也是后续版本的演进方向:

1. **谁驱动**:不是固定流水线,而是模型自己读证据、自己决定记什么(本版 P0 落地);
2. **何时触发**:不是书完本才复盘,重试/整段重写等强信号要能当场反思(P1);
3. **如何验证**:候选改进先对历史章节重放——「早有这条规则,过去的重写是否可以避免」,量化变好才准入(P2,重放验证)。

## 2. 三档自治旋钮(用户级,默认 off)

争议点不在「做不做」而在「自主到什么程度」,所以做成三档而不是布尔开关:

| 档位 | 采集 | 入库状态 | 注入 |
|---|---|---|---|
| `off`(默认) | **不采集、不反思、不注入**——复盘端点直接 409,无任何行为差异 | — | 无 |
| `confirm`(L1) | 复盘产出候选 | `pending`,作者逐条确认/忽略 | 仅 `confirmed` 注入 |
| `auto`(L2) | 复盘产出候选 | 自动 `confirmed`(可见、可删、可改回) | 同上 |

硬规矩:**off = 停止采集**,不是「只停止应用」;多用户按 `user_id` 严格隔离,记忆不跨用户。L3(自动改写自身口径包 + 重放验证 + 灰度)本版不做,留待 P2。

## 3. 数据与资产

- `evolution_prefs`(新表,create_all 自动建):`user_id` PK + `level`,用户级旋钮。
- `evolution_memories`(新表):`user_id`(index)/`project_id`(**不加 FK**,项目删了记忆还在)/`kind`(style=文风特征 / lesson=教训 / preference=偏好)/`content`(可执行规则,≤200 字)/`evidence`(出处,≤120 字)/`confidence`/`status`(pending/confirmed/dismissed)/`source`(JSON:书名、总评等)。
- 只学**作者确认过的定稿**(approved 章),绝不把 AI 原稿当正面样本;删改痕迹(diff)只用于提炼教训,不进文风样本。

## 4. 复盘引擎(证据 → 反思 → 记忆)

`app/engines/evolution/`(evidence.py + reflect.py,纯函数与引擎分离,便于单测):

- **证据包**(`gather_project_evidence`):① 章节状态统计(approved/总数/字数);② 作者采纳样本:取 3 章 approved 的 `final_content` 节选;③ 动手痕迹:对有草稿与定稿差异的章用 `difflib` 提取主要删改片段(作者删掉/改掉的东西是教训的最硬证据);④ 作者指令:GenInput 里 intent-readback / revise-plan / chapter-revision 等的用户输入摘录。全链有字数预算(样本 ~7.5k、痕迹 ~3k、指令 ~6k),防止 prompt 膨胀。
- **反思**(`run_retrospective`):`ask_llm_json` + 新 `Task.EVOLUTION`(审校档,写手与审校分模型的既有原则),contract `{"memories": list}`,要求 3-8 条、每条带出处、content 具体可执行、教训只从删改/重写/补充说明里提炼、没有证据的宁可不写。
- **收敛落库**(白名单 + 截断 + 对同用户已有记忆去重):confirm 档落 pending,auto 档落 confirmed;复盘全程 `record_gen_inputs(kind="evolution-retrospective")` 留痕。

## 5. 回注通道(一处注入,全链继承)

注入点只选**开书回读**(`intent-readback`):确认过的记忆渲染成「作者历史偏好与教训」块,拼进回读 prompt;模型把文风写进卡片的 flavor、把「必须延续/不要出现」写进 must/avoid——卡片确认后经 `render_intent_block` 传遍架构/骨架/蓝图/正文,**下游模板一字不动**。注入什么、注了几条,以 `kind="evolution-injection"` 留痕。空记忆时 prompt 与现状完全一致(老用户零影响)。

## 6. P0 边界(本版不做的,及为什么)

- **不做 L3 自主进化**:不自改口径包/门槛,不做重放验证——先让「证据→记忆→回注」的闭环跑起来,验证记忆质量,再谈自动化(docs/34 的教训:门槛类机制没标定就自动执行必然空转)。
- **不做章级连续反思**:重试次数在 `llm_usage` 无 project 维度,需先补留痕(P1);本版复盘是书级、手动触发(作者点「复盘」)。
- **不做统计指纹**:文风条目由 LLM 从样本提炼,docs/35 的指纹引擎开工后,可在证据包里加一节量化指纹,提升条目置信度——接口已按「证据包」设计,加料不动架构。
- **不做自动触发**:不挂「标完本」钩子,作者主动点,复盘成本(一次审校档调用)可见可控。

## 7. 隐私与红线

1. 记忆是**用户资产**:全部端点按当前用户过滤;可单条删、可一键清空;删除立即生效于下一次注入。
2. off 档不产生任何记忆数据;关闭开关不删除已有记忆(保留资产,停止增量),要全删用「清空」。
3. 记忆条目必须有出处(evidence),禁止无证据泛化;注入上限 8 条、每条 ≤200 字,防 prompt 膨胀。
4. 提炼产物只进该用户的上下文,不进任何全局共享资产。

## 8. 施工步骤(本版已实现)

| 步 | 内容 | 验收 |
|---|---|---|
| S1 | 模型两张新表 + 注册 | create_all 建表;老库启动零迁移 |
| S2 | 证据包 + 反思引擎 + 收敛去重 | 纯函数单测;截断/白名单/去重各有边界用例 |
| S3 | `/api/evolution` 配置与记忆 CRUD(用户隔离) | off/confirm/auto 合法性;跨用户 404 |
| S4 | `POST /api/projects/{pid}/retrospective` | off→409;无 approved 章→400;LLM 坏输出→502 且不落库 |
| S5 | 回读注入 + 留痕 | 有确认记忆→prompt 含之;无→prompt 与现状一致 |
| S6 | 前端:设置页「进化」卡(旋钮+记忆列表)+ 项目卡「复盘」入口+复盘弹窗 | vitest:档位切换/逐条确认/删除/清空/off 引导 |

**门禁**:backend `python -m pytest -q` 全绿 + 新增用例;frontend `npx tsc --noEmit` + `eslint` + `vitest run` 全绿。

## 9. 待拍板(P1/P2)
